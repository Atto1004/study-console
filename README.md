# 학습 관제탑 (Study Console)

대학생 학습 코디네이터 웹앱. 시간표를 올리면 과목이 책장에 꽂히고, 시험 날까지 무엇을 얼마나 어떻게 공부할지 관리한다.

> 씽크빅(모르는 지점 진단) × 듀오링고(매일 하게 만드는 루프) × 학습 코디네이터(냉정한 전략 지시)

---

## 파일 구조

```
index.html        앱 본체 — HTML 한 파일. 빌드 없음, 외부 의존성 없음
demo.html         공유용 데모 — 개인 데이터 없이 '학기 중' 샘플로 채워짐
docs/기획서.md     전체 기획 문서 (21개 섹션)
```

**끝이다.** 번들러도, npm도, 프레임워크도 없다. `index.html`을 브라우저로 열면 그대로 돌아간다.

---

## 개발 방법

### 1. 브라우저에서 바로 확인
```
index.html 을 브라우저로 열기 (더블클릭)
```
수정 → 새로고침. 그게 전부다.

### 2. 구조

한 파일 안에 4개 층으로 쌓여 있다. **아래층이 위층을 덮어쓴다**(CSS 캐스케이드).

| 순서 | 영역 | 내용 |
|---|---|---|
| 1 | `<style>` 기본 토큰 | 색·타이포·컴포넌트 기본형 |
| 2 | 컴포넌트 CSS | 책장 · 달력 · 타임라인 · 재수강 행 |
| 3 | 유동 타이포 · 반응형 | `clamp()` 기반 화면별 크기 |
| 4 | **모바일 우선 + APPLE UI LAYER** | 최종 색·모서리·버튼 (여기가 최종 승자) |

> ⚠️ **색이나 버튼을 고칠 때는 반드시 4번 층에서 고쳐야 한다.** 위층에서 고치면 Apple 레이어에 덮여서 반영이 안 된다. 실제로 그 실수를 한 번 했다.

JS는 그 아래 한 덩어리:
- **데이터** — `blank()` / `migrate()` / `load()` / `persist()`
- **도메인 계산** — `planned()` `coverage()` `attStats()` `studyMode()` `phase()` `retakeCandidates()`
- **화면** — `renderShelf()` `renderToday()` `renderCal()` `renderGrade()` `renderCourse()` `renderSet()`
- **시트** — `openSheet()` 기반 모달 (모바일에선 바텀시트)
- **시드** — `seedEngMath()` 등 과목별 강의계획서 데이터

### 3. 데이터 저장

```
localStorage  ← 즉시·오프라인 (기본)
     +
페이지 자체에 굽기  ← 「저장」 버튼 → artifact.publish(serialize())
```

`serialize()`가 DOM을 복제해서 동적 컨테이너를 비우고 `<script id="state">`에 JSON을 넣어 통째로 재발행한다. 그래서 **같은 링크를 다른 기기에서 열면 데이터가 따라온다.**

---

## 배포

각자 자기 Claude 계정에서 `index.html`을 아티팩트로 발행하면 **각자의 URL과 각자의 데이터**를 갖게 된다. 서로 간섭하지 않는다.

GitHub Pages로 하나의 URL을 쓸 수도 있지만, 그러면 「저장」(자체 재발행) 기능이 동작하지 않는다. 데이터는 각자 브라우저에만 남고, 백업은 **설정 → 데이터 → JSON 내보내기**로 해야 한다.

---

## ⚠️ 커밋하면 안 되는 것

**개인 데이터가 구워진 HTML을 절대 커밋하지 말 것.**

「저장」을 누른 배포본에는 `<script id="state">` 안에 **성적·시간표·출결 기록이 전부 평문으로** 들어 있다. `.gitignore`에 막아뒀지만 파일명을 바꿔서 올리면 뚫린다.

커밋 전 확인:
```bash
grep -c 'id="state">null' index.html    # 1 이어야 한다
```

### 지금 저장소에 들어 있는 것

`index.html`의 시드 데이터에 **교수 실명 6명과 학수번호**가 들어 있다. 수강신청 시스템에 공개된 정보라 민감하진 않지만, **저장소를 public으로 바꾸거나 GitHub Pages를 켜면 그대로 노출된다.** private 유지를 권장한다.

## 협업 규칙

1. `main`에 직접 푸시하지 말고 브랜치를 파서 PR을 올린다.
2. **한 파일이라 충돌이 잦다.** 작업 전에 누가 어느 영역을 건드리는지 정하고 시작할 것.
   - 예: A는 CSS(1~4층), B는 렌더 함수, C는 도메인 계산
3. 커밋 메시지는 무엇을 왜 바꿨는지 한국어로 적는다.
4. 기능을 추가하면 `docs/기획서.md`의 로드맵 표도 같이 갱신한다.
