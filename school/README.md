## .191 가상 학교 통합

로비·칠판·김주영 스앵님과 메인·공부하기·진도관리·수업자료·출결·과제를 같은 학교에서 사용합니다. 기본 수업은 전체 개념·예제·확인 흐름이고, 시험 문제 미션은 직접 선택합니다. 기존 오늘 공부·타이머·개인 공부·복습·성적·자료실을 내부 화면에서 사용합니다.

`GET/POST /api/school/session`은 `school_learning_v1.activeSession`에 수업·단계·목적·보충 복귀 대상과 revision을 저장합니다. 관리 화면 이동과 새로고침 뒤 이어갈 수 있고, 다른 화면의 수정은 CAS로 보호합니다. 풀이 저장 오류에서는 현재 입력을 보존하고 최신 풀이와 비교한 뒤 저장합니다. 원문 변경은 확인해야 하며 AI 피드백은 독립 정답으로 통과시키지 않습니다.

지난 과제는 지난 기록에서 확인합니다. 계속 진행을 직접 선택하면 진행 목록에 돌아옵니다. 제출·풀이 완료·메인 숨김은 별도 상태이며 숨긴 과제도 마감 당일 표시합니다.

독립 메모리 검수 및 실제 브라우저 검증 완료: 정역학 저장→새로고침→풀이 복원, 관리에서 수업 복귀, 선택형 시험 3문제 완료, 과제 필터, 900px/899px/390px 배치. 실제 아이패드 펜슬·실물 대표기기 입력은 미검증입니다. 브라우저 테스트는 `?test=1` 메모리 원장만 사용했습니다.

## .188 메인 상담과 미션 학습

주 메뉴는 메인·공부하기·진도관리·수업자료·출결·과제다. 메인의 D-14 시험 대비·D-day와 오늘 계획은 활성 학기 원본을 사용한다. 스앵님과 상담하고 제안된 계획을 선택해 적용한다. 캘린더를 확인하지 못하면 시간 배치를 확정하지 않는다. 공부는 문제 미션/개념 공부를 선택하고 펜슬·공책·화면 풀이 방식을 바꿀 수 있다. 초안은 자동 저장하며 제출 시 사진/필기/텍스트를 보존한다. AI 피드백은 판정 후보이고 독립 정답이 아니다.

서버 school_workspace는 기존 로컬 자료를 10분마다 색인하고 범위 후보를 근거와 함께 제공한다. LMS 기존 동기화는 자료 링크 메타데이터이며 파일 수집으로 표시하지 않는다. 과목/회차 연결과 수업 범위는 직접 수정·확정한다. 공식 출결 연동은 없으므로 종료된 수업은 한 번 확인하고 기록한다. 두 화면 동시 수정은 workspaceRevision으로 보호하며 오래된 전체 상태 저장은 409로 거절한다. 펜슬 입력은 실제 기기 검증 여부를 완료 보고에 별도로 표기한다.

## .187 통합 버전

대표님 10/7 지시: 기존 버전과 새 버전을 구분해 두지 않고 이전보다 나은 한 앱으로 통합한다. 주 메뉴는 공부하기·진도관리·과제다. 오늘·계획·타이머·시험·암기노트·개념지도·기존 기록과 출결·시간표·성적·회차 편집은 동일한 앱 화면 안에서 사용한다. 기존 엔진은 `integrated.js`로 과목·회차를 지정해 재사용하고 원본은 유지한다. 수업 기록 수정은 원래 study_state에 저장되며 진도관리에서 다시 읽는다. 검사 모드에서는 실제 원장의 통합 편집을 열지 않는다.

## .183 혼자 풀기는 공부하기에

혼자 풀기·스앵님 코칭 자료는 공부하기에서 과목을 골라 엽니다. `_private/submit.json`의 practices에 보존하며 files는 제출 관련 파일만 담습니다. 과제 화면에는 연습·개념 학습 버튼을 표시하지 않습니다.

## .182 진도관리 의미 수정

진도관리는 수업 내용과 자료 관리입니다. 과목별 실제 수업 범위, 강의계획·예고 근거, 날짜별 자료와 교재·공통 강의자료를 보여줍니다. 미래 회차는 별도 목록에 예정으로 표시합니다. `knowledge/materials.json`, `knowledge/sessions.json`을 원본으로 읽고, `docs/tools/build_class_files.py`가 기존 library 색인과 서빙 사본에서 `_private/class-files.json` 조회용 목록을 만듭니다. 파일 추가 후 이 목록을 다시 생성합니다. 성취 기록은 더보기의 상세 학습 기록에 있습니다.

## .181 세 파트 구성

공부하기는 수업·선수 개념·복습, 진도관리는 과목별 학습한 수업·직접 풀이·목표와 재시도, 과제는 마감·제출 확인·제출 파일을 맡습니다. 자료실·상세 기록·설정·과목 목록은 더보기에 있습니다. 기존 학생 기록과 주차별 진도 관제탑을 사용하며 수업 열람을 완료로 처리하지 않습니다.

## .180 학습·과제 분리

상단 학습·과제 버튼으로 별도 화면을 엽니다. 과제 영역은 기존 자료 색인·할 일·현재 학기 주차 기록에서 과제를 읽고 과목·진행·제출 확인으로 구분합니다. 마감·제출본·근거를 보며 필요한 개념 학습으로 들어갔다가 과제 버튼으로 돌아옵니다. 작업 완료와 제출 확인은 별개이며 실제 상태 변경은 기존 관제탑에서 합니다. 새 제출 원장을 만들지 않습니다.

## .179 기능 마무리

- 자신의 말로 설명하면 AI가 실제 답변 인용을 확인하고 오개념·확인 질문·선수 보충을 제안합니다. 보충 후 원래 수업으로 돌아오며 관찰 기록을 다음 코칭에 전달합니다. AI의 평가만으로 이해 완료나 정답을 만들지 않습니다.
- Claude/Codex의 기존 사용량 계측에서 최신 잔여 비율이 높은 모델을 먼저 선택합니다. 10분을 지난 값과 리셋 이후 값은 제외합니다. 이는 절대 토큰 수 비교가 아닙니다.
- 자료실에서 회차별 판서·사진 원본을 열고 한 장씩 Codex로 판독·대조할 수 있습니다. 12MB 이하 JPG/PNG/WebP를 지원하며 원문·불확실한 위치·정리본 대조 의심을 별도로 보존합니다. PDF 안의 이미지와 손글씨 정확성은 별도 확인이 필요합니다.
- 교수 규칙을 수업·출제·풀이·주의 유형과 출처·날짜로 기록하고 과목 전략과 함께 코칭·생성에 전달합니다. 내용 검토 대기 교재도 학습 기록을 차단합니다.
- 디자인은 .178 상태를 유지합니다. 디자인 최종 승인으로 간주하지 않습니다. TTS는 이번 완료 범위에서 제외합니다.

## .178 디자인

- 로비 안내 데스크·교실 번호·과목 안내판과 이어가기 영역을 정리했습니다.
- 교실 판서·교사·하단 대화의 배치를 웹·아이패드 가로·세로에서 조정했습니다. 상담·자료실·학습 기록·설정은 같은 창 디자인을 사용합니다.
- TTS는 이번 디자인 완료 기준에서 제외하며 연결 설정이 없을 때 듣기 버튼을 숨깁니다.
- `design.css`가 학교 화면의 최종 배치와 미감을 담당합니다. 기존 학습 기능과 데이터는 유지합니다.

## .176 보완

- 생성 직후 다른 엔진이 모든 단계를 검사합니다. 오류 교재는 정답 기록을 막고, 검토 연결 실패는 미검증으로 보존합니다. 수업의 근거에서 재검토할 수 있습니다.
- 녹음 원본·교정본·정리본과 날짜에 연결된 교수 PDF의 추출 텍스트를 대조합니다. 인용·줄·PDF 페이지는 원문과 일치해야 합니다. 같은 엔진의 두 번째 근거 검토로 반대 해석과 이미 있는 설명을 다시 확인합니다. 이는 다른 엔진 독립 검증이 아닙니다.
- 정리본 일부만 전달되면 누락 판정을 허용하지 않습니다. PDF 사진과 이미지 수식은 자동 검증에 포함하지 않습니다.
- 교수 HTML 분석은 미검증 참고로 읽고 출처 확정 규칙과 구분합니다. 과외 대화는 하단 영역에 통합했습니다.
- 과목별 선수 개념, 회전·키보드에 따른 판서 재분할, 판서·응답 듣기의 중단, 기기 화면 점검을 보완했습니다.
- 실제 Fish 키·reference ID가 없어 음성 서비스 응답은 미검증입니다. 실제 iPad Safari도 기기 접근이 없어 미검증입니다. 다른 검토 모델이 연결되지 않으면 교재 내용 검증은 대기 상태가 됩니다.

실행 주소: `https://desktop-ipg931s.tail9069cc.ts.net/study/`

atom의 기존 로그인과 서버를 사용합니다. 정적 파일만 여는 GitHub Pages에서는 학교 API가 없어 실행되지 않습니다. 기존 출결·과제·시험 관제탑은 `../index.html?view=classic`으로 연결됩니다.

## 구현한 흐름

- 로비의 7개 과목 교실, 상담실, 자료실, 학생 기록, 모델 설정.
- 목표·학습 시간·현재 상태를 듣고 짧게 진단합니다. 처음 배우는 경우 선수 개념부터 출발하고, 계획을 적용한 뒤 다음 학습으로 이어집니다.
- 기존 47회 수업과 91개 개념을 의미 단위 판서로 변환합니다. 부족했던 선수 기초 31개는 `foundations.json`에 자체 작성했고 교수 자료와 구분했습니다.
- 칠판을 끌거나 내부 스크롤하지 않습니다. 긴 내용은 앞·다음 판서로 나눕니다. 웹, 아이패드 가로·세로에 맞춰 교사와 칠판 위치를 바꿉니다.
- 읽음, 오답, 도움받은 정답, 독립 정답을 구분합니다. 오답의 선수 개념으로 돌아갔다가 원래 문제로 복귀할 수 있습니다. 하루/3일 뒤 지연 복습을 제안합니다.
- 현재 판서·출처·학생 계획·풀이·질문·확정 교수 규칙을 전달해 과외 대화를 진행합니다. 접거나 새로 열어도 해당 수업의 최근 대화를 복원합니다.
- Claude/Codex 선택과 오류 시 자동 폴백. 기억은 모델 세션이 아닌 서버의 `school_learning_v1`에 저장합니다.
- 원자료 기반 보충 수업을 구조화된 응답으로 생성합니다. 보기·정답·풀이·판서 길이를 검사하고 원문과 별도로 저장합니다. 학생 기록에서 다시 엽니다.
- 교수 특징·출제/풀이 규칙은 출처·날짜·근거 등급과 함께 기록합니다. 기존 교수 분석 원문도 미검증 상태를 표시해 엽니다.
- 색인의 확보 건수, 녹음 대조 대기, 정리본에 명시된 중단·누락·재구성 위치를 줄 번호로 표시합니다.

## 검증과 범위

Python 회귀 검사 39건, 학습 규칙 5건, 새 학교/기존 관제탑 jsdom 오류 0건. 실행 중 서버에서 인증·채점·저장·중복 요청, 실제 과외 응답, 실제 생성·저장·재개, 서술형 피드백과 사진 판독을 확인했습니다. 브라우저와 jsdom에서 상담·계획·수업·서술형 피드백·선수 보충·원래 수업 복귀를 확인했습니다. 1180×720, 1024×768, 834×1194 화면을 검사했습니다. 실제 iPad Safari 장치는 직접 확인하지 않았습니다.

모바일 화면의 완전한 별도 설계와 A++O 전체 UI 변경은 이번 학습앱 구현 범위에 포함하지 않았습니다. 작은 화면에서 기존 기능을 사용하는 기본 대응만 있습니다.

Fish 연결 코드는 있지만 서버에 `FISH_API_KEY`, `FISH_REFERENCE_ID`가 없어 실제 음성은 확인하지 못했습니다. 자격정보는 코드·브라우저·커밋에 넣지 않습니다. 설정 후 서버를 다시 시작해야 합니다.

자동 생성 교재는 별도 엔진의 내용 검토가 끝나야 학습 기록을 쌓습니다. 교수 수업자료와 전체 녹음의 의미 대조는 회차별로 요청하며 모든 자료의 대조를 완료한 상태는 아닙니다. 짧은 진단이나 한 문항의 정답을 전체 실력·성적 보장으로 집계하지 않습니다.

## 재현

검사 전용 의존성은 `.test-tools`에 설치합니다. 런타임은 프레임워크 없이 HTML/CSS/JavaScript, Python 표준 라이브러리로 동작합니다. 교수 PDF 텍스트 대조에는 선택적으로 PyMuPDF를 사용합니다. 없으면 PDF 미대조로 표시합니다. 수식 렌더러 KaTeX는 현재 CDN을 사용하므로 인터넷이 없으면 수식 원문이 표시됩니다.

```powershell
npm.cmd install --prefix .test-tools --no-audit --no-fund --ignore-scripts jsdom@27.4.0 prettier@3.6.2
python -X utf8 docs/tools/build_school_fixture.py
node --test school/learning.test.mjs
node docs/tools/school_smoke.cjs
node docs/tools/main_boot_check.cjs
```

atom 저장소에서:

```powershell
python -X utf8 -m unittest tests.test_school tests.test_school_quality tests.test_school_tutoring tests.test_school_models_visual
python -X utf8 tests/school_http_check.py
python -X utf8 tests/school_http_check.py --coach --teachback --generate --compare --inspect
```

`?test=1`과 `X-School-Test: 1`은 인증을 유지한 채 별도 메모리 원장을 사용합니다. 실제 학생 기록에는 쓰지 않으며 서버 재시작 때 사라집니다.

## 저장과 복구

기존 `study_state`, `mastery`, 교수 자료 원문을 덮어쓰지 않습니다. 새 원장은 이벤트 ID로 병합하고 중복을 제거합니다. 저장 실패 시 화면에 미저장 수와 재시도를 표시하며, 미저장 상태에서 페이지를 떠날 때 경고합니다. 학생 기록에서 JSON을 내려받을 수 있습니다. 이 기능은 DB 자체의 백업/복구 완료를 뜻하지 않습니다.

학교 기본 진입을 중지할 때는 기존 관제탑 `?view=classic`을 사용합니다. 서버 모듈을 제거할 필요 없이 자료 원문을 열 수 있습니다. 원격 push와 실제 서버 실행 상태는 세션 완료 기록에서 확인합니다.
