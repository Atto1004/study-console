# 학습앱 개편 최종 기획안 — 「가상 학교」 (아톰 · 오타 회의 결정, 2026-10-04)

> 판정: 오타 GREEN · 아톰 동의. **대표님 컨펌 전 구현 착수 없음.**
> 근거 문서: ui-restructure-1004.md(1차) · 1004b.md(문제 중심) · 오타 3차안 · 회의 1차(아톰 조정 4건 전부 합의)

## 1. 목표와 원칙
- 목표: 대표님을 **효율적으로** 공부시키는 것. 재미(게임)는 수단이다.
- 원칙: ① 첫 행동까지 버튼 1번 ② 스앵님은 하단 도크 하나 ③ 설명 글 최소((i) 안으로) ④ 문제 먼저, 단 모르는 게 많을 때는 수업 토막부터 ⑤ 지어낸 장식 · 빈 공간 금지 ⑥ 기존 학습 기록은 절대 잃지 않음

## 2. 두 갈래
| | 아이패드 · PC = 가상 학교 | 폰 = 학습 수첩 |
|---|---|---|
| 첫 화면 | 학교 단면도 + 「다음 공부 1개 · 이어 풀기」 | 오늘 목록 + 이어 풀기 |
| 공부 | 과목 교실에서 문제 · 수업 | 같은 문제 · 수업을 한 열로 |
| 관리(계획 · 마감 · 자료 · 설정 · 학점) | 상단 「관리」 하나로 모음(삭제 아님) | 오늘 · 과목 · 계획 탭 |
- 문제 · 풀이 기록 · 스앵님은 두 갈래가 **같은 것**을 쓴다(따로 만들지 않음).
- 화면 회전 · 키보드로 모드가 갑자기 바뀌지 않음.

## 3. 학교 공간 (첫 버전은 셋 + 공용 설비 둘)
| 공간 | 하는 일 | 효율에 보태는 것 |
|---|---|---|
| 교실동(과목 교실) | 장 · 절별 문제, 수업 회차(「오늘 수업」 입구), 자료 책장, 기록 | 공부 중 필요한 것을 한 장소에서 |
| 자습실 | 과제 · 복습을 섞은 오늘의 대기 목록 | 과목을 고르지 않고 이어 풀기 |
| 도서관 | 전체 자료 검색(교실 책장과 같은 원본) | 과목 · 회차를 모를 때 찾기 |
| 게시판(설비) | 마감 · 공지 · 확인 요청 → 해당 과제로 바로 | 처리할 것에서 바로 이동 |
| 시간표(설비) | 계획 · 루틴 · 예약 | 다음 공부와 확보 시간 |
- 만들지 않는 것: 교무실(질문은 도크), 시험장(시험 범위는 교실 필터로 — 실제 모의시험 기능이 생기면 검토), 운동장 · 매점 · 기숙사 · 공사 예정 건물.

## 4. 하루 흐름 (일상 화면 2개: 학교 · 공부)
학교 → **이어 풀기(1번)** → 교실의 문제 또는 수업 토막 → 막히면 도크(힌트 → 개념 → 해설, 같은 화면) → 채점 → 다음 → 「오늘 마치기」(그 자리에서 기록 펼침, 저장은 매 행동마다)
- 「다음 공부 1개」 고르기: 진행 중 → 남은 과제 연결 문제 → 약점 복습. **선수 개념이 비어 있고 막힌 단계가 확인되면 수업 토막을 먼저**, 기록이 없는(미평가) 개념은 「모름」으로 단정하지 않고 짧은 진단부터.
- 교실 첫 화면: 문제 목록이 기본 + 「오늘 수업」(가장 최근 회차를 스앵님이 다시 해 줌) 버튼 하나.

## 5. 화면 (아이패드 1040×918)
- 상단 56: 학교로 · 현재 과목 · 확인 · 관리
- 본문 718: 학교 지도 또는 공부 내용(공부 중에는 지도 · 장식 사라짐)
- 하단 144 스앵님 도크: 112×112 초상(어깨 위, 어두운 단색 배경) + 이름 · 상태 + 최근 설명 두 줄 + 질문창. 접힘 64 · 펼침 320. 표정만 상태(대기 · 준비 · 설명 중 · 완료)에 맞춰 바뀜, 무작위 동작 · 입모양 흉내 · 레이저 없음.
- 폰: 상단 48 · 도크 112(얼굴 48) · 대화 펼침 최대 55% · 키보드 올라오면 메뉴 숨김.
- 학교 그림: 정면 2D 단면도(복도 + 과목 문 + 자습실 · 도서관). 한 화면에 다 보임. 정적 그림 + 진짜 버튼, 그림이 안 떠도 버튼은 동작. 터치 최소 44.
- 디자인 토큰: 밝은 배경 · 초록 주색 · Pretendard · 간격 4~32 · 모서리 10/12 · 그림자는 펼친 도크만. 도트 글꼴 · 사진 배경 · 황동 테두리 없음.

## 6. 게임 요소
| 넣음 | 학교 표현 |
|---|---|
| 문제 정복 | 문제 옆 「혼자 ✓」(도움 · 오답 없이 2회 연속) |
| 단원 진행 | 단원 명패 「혼자 해결 n / 등록 m」 |
| 재도전 | 오늘 책상 위 미완료 문제 |
| 연속 등교일 | 학습 출석부(실제로 푼 날만, 대학 출결과 별개) |
| 완료 반응 | 명패 체크 · 도크 표정 |
- 넣지 않음: XP · 레벨 · 호감도 · 하트 · 순위 · 잠금. (기존 기록 데이터는 지우지 않고 화면에서만 뺌)

## 7. 그림 · 제작 방법
- 시안: **아톰이 Figma 로 4장**(학교 · 문제 풀이 · 도크 펼침 · 폰 오늘) — 실제 문제 · 긴 수식을 넣어서. 오타 검토 → 대표님 컨펌.
- 그림은 Figma 도형 · SVG + 기존 스앵님 그림으로 시작(생성 이미지 없이 구조 결정). 승인 뒤 공통 배경 · 문 · 책장 부품 우선, 회차별 배경 · 영상 · 새 캐릭터는 뒤로. (이미지 생성 크레딧 잔량은 미확인)

## 8. 단계와 일정
| 단계 | 내용 | 통과 조건 |
|---|---|---|
| ① 문제 은행 | 625문제 색인(완료) — 실제 작업본 대조 | 기존 문제 · 기록 연결 유지 |
| ② 공통 풀이 | 한 단원 완성, 학교 · 폰 같은 부품 | 답 저장 · 재접속 · 기존 링크 |
| ③ 공통 도크 | 문제 문맥 · 도움 기록 · 늦은 답 분리 | AI 실패에도 풀이 계속, 질문창 하나 |
| ④ 다음 공부 | 진행 중 → 과제 → 약점 + 수업 토막 규칙 | 미분류 · 후보 없음 처리 |
| ⑤ 두 갈래 껍데기 | 시안 컨펌 후 학교 · 폰 진입 | **설정 한 번으로 옛 화면 복귀 · 새 화면 기록을 옛 화면이 읽음** |
| ⑥ 확장 | 덱 · 교실 32회차 연결(원본 생성기도) | 안 바꾼 회차는 옛 화면으로 |
| ⑦ 성취 · 검수 | 명패 · 출석부 · 장식 | 아이패드 · 폰 · 뒤로 · 저장 복원 |
- **시험 전(10/19 이전): ①~④ + 정역학 교실 하나의 학교 시범**(학교 지도: 교실동 · 자습실 · 도서관 문 + 도크 + 폰 수첩 오늘 화면). 나머지 과목 교실은 옛 화면으로 연결.
- **시험 뒤: ⑤~⑦ 전체 전환.** 10/19 직후에도 시험이 남아(10/20 · 21 · 23) 그날을 전환일로 잡지 않음.
- 컨펌 순서: **이 기획안 컨펌 → Figma 시안 4장 컨펌 → 구현.**

## 9. 위험과 대책
- 시험 2주 전 대개편 → 시험 전에는 정역학 한 교실 시범까지만, 옛 화면 항상 남김.
- 레이어가 70개 넘게 쌓인 구조 → 새 CSS 덧붙이기 대신 공통 부품으로 새로 짜고, 옛 화면은 복귀용으로만 유지.
- 학교 · 폰을 따로 만들면 기록이 갈라짐 → 공통 풀이 · 저장을 먼저.
- 학교를 걸어 다니게 만들면 느려짐 → 이동은 화면 전환 한 번.

## 10. 회의에서 갈렸다가 합의한 것
1. 교실 첫 화면: 오타 「문제부터」 ↔ 아톰 「수업도」 → **문제 기본 + 「오늘 수업」 입구, 다음 공부는 문제 또는 수업 토막**
2. 시험 전 범위: → **정역학 교실 하나 시범**으로 구체화
3. 시안: → **기획 컨펌 → 시안 컨펌 → 구현** 두 번 컨펌
4. 「심플 기능은 폰으로」: → **삭제가 아니라 학교 주 화면에서 빼고 「관리」로 모음**
