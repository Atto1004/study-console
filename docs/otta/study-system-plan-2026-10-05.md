# 학습앱 시스템 개편 개발 계획

대표님과의 기획 대화를 정리한 계획안. 이 문서의 커밋은 구현 완료나 배포를 뜻하지 않는다. 기존 코드와 다른 작업의 변경은 포함하지 않는다.

## 확정된 요구사항

- 아이패드·웹용 게임 UI 우선. 모바일 상세 디자인·구현은 이후 진행한다.
- 대표님 1인칭 시점의 학교. 가벼운 2D 고정 장면을 사용한다.
- 미감은 핵심 설계 기준이다. 기존 카드 위에 배경만 추가하는 방식으로 끝내지 않는다. 최종 시각 스타일은 시안 검토 후 결정한다.
- 상담실·과목 교실·자습실·자료실을 연결한다. 현재 수업으로 바로 돌아갈 수 있어야 한다.
- 칠판 내부 스크롤·드래그 금지. 읽을 수 있는 크기로 배치하고 긴 내용은 의미 있는 단계로 나눈다.
- 최신 스앵님 외형만 사용한다. 로딩 중 임시 외형이 먼저 나타나는 현상을 제거한다.
- 게임 모드와 향후 모바일 텍스트 모드의 기능·데이터·판정·권한은 동일하다. 표현과 동선만 달리한다. A++O 전체에도 같은 원칙을 적용한다.
- 교수별 규칙과 과목별 전략을 먼저 정리하고, 교수 수업자료를 근거로 교재를 생성·보충·변환한다.
- 자료 완전성, 교재 정확성, 대표님 이해도는 별도 상태로 관리한다.
- 스앵님은 질문과 답에 따라 설명·힌트·문제를 조정하는 쌍방향 과외를 진행한다.
- 모델 교체가 가능해야 한다. 수업 기억은 앱이 보관하며, 교체 후 같은 단계에서 이어간다. 능력과 확인 가능한 한도·속도·비용을 고려한다.
- Fish TTS는 짧은 설명과 질문에 연결한다. 말 끊기·다시 듣기·속도·음소거를 제공한다. 성능·비용·연결 가능 여부는 구현 전 확인한다.

## 현재 확인한 문제와 조사 범위

앱 소스, 교재 3종, 생성 코드, 일부 교수 분석을 읽었다. 실제 아이패드 화면, 전체 서버 동기화, 원자료 누락, 전체 문제 정확성은 미검증이다.

- 자료·교수 분석·과목 규칙이 여러 문서와 데이터에 분산돼 있다.
- 슬라이드 생성은 HTML 구조 추출과 분량 기준 분할을 사용한다. 넘침을 스크롤로 허용하는 경로가 있다.
- 서술형 자기채점이 quiz 정답 근거로 기록된다. 일부 시험 준비 판단은 20분 공부 기록을 사용한다.
- 다음 공부가 화면의 첫 교실 열기 버튼에서 추출된다.
- 자동 저장 실패를 숨기는 경로와 늦은 서버 응답이 현재 상태에 적용되지 않는 경로가 있다. 실제 충돌 결과는 서버 확인이 필요하다.
- 함수 래핑·교체가 누적돼 화면과 실행 순서 의존성이 크다.

## 개발 단계와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1. 현황 조사 | 자료 생성·교수 기록·학습 근거·저장·모델 연결을 추적하고 UI 문제 재현 | 확인/미확인 구분, 재사용 목록, 첫 단원 선정 |
| 2. 디자인 | 로비·상담실·교실·자습실을 실제 긴 수식·그림·답안으로 시안화 | 대표님이 미감과 배치를 검토한 시안 확보 |
| 3. 자료 체계 | 과목→수업일→개념에 슬라이드 페이지·클로바 시각·판서·필기·과제 연결 | 원자료까지 추적 가능, 누락 의심 근거 표시 |
| 4. 기록 보호 | 저장 실패·재시도·늦은 응답·충돌 처리, 자기평가와 검증 결과 분리 | 기록 손실 방지, 평가 근거, 새로고침·기기 변경 이어하기 검증 |
| 5. 수업 생성 | 목표→기초 확인→설명→질문→함께 풀기→독립 풀이→보충 구성 | 한 단원을 출발점부터 독립 풀이까지 진행 가능 |
| 6. 스앵님 | 상담 결과 적용, 답변별 분기, 공통 수업 상태, 모델 교체, TTS | 오답·모름에 대응하고 장애·교체 시 진행 보존 |
| 7. 게임 UI | 검토한 1인칭 장면 구현, 칠판 배치, 최신 외형, 필요 자원 로딩 | 실제 아이패드·웹에서 상담→수업→복습 완료 |
| 8. 확대 | 과목별 전략 적용, A++O 디자인 연계, 이후 모바일 구현 | 기능 동등성·학습 기록 연속성 검증 |

## 자료와 판정 규칙

- 대조 상태: 대응 확인 / 추가 설명 / 누락 의심 / 불일치 / 미확인.
- 녹음 언급이 슬라이드에 없다는 이유만으로 누락을 확정하지 않는다. 판서·구두 설명·녹음 오류 가능성을 남긴다.
- 교수 규칙은 풀이·표기·채점·출제 관련 항목별로 출처·날짜와 명시/관찰/추정/미확인을 기록한다.
- 교수 원자료와 앱의 보충 설명을 구분한다. 새 자료는 관련 수업만 갱신한다.
- 공부 시간, 자기평가, 도움받아 해결, 독립 해결, 이후 재확인을 구분한다.
- 교재 버전과 평가 근거를 보존한다. 오류 정정은 영향을 받은 평가를 재확인하도록 처리한다.
- 필기 인식은 인식한 식을 확인·수정한 뒤 평가한다.

## 첫 구현 범위

한 과목·한 단원에서 상담→쌍방향 수업→독립 풀이→복습을 완성한다. 텍스트 입력·TTS 출력·기본 모델 교체를 연결한다. 자유 이동 3D, 복잡한 보상, 음성 입력, 모바일 상세 구현은 뒤로 둔다.

과목·단원, 최종 미감, 서비스별 연결 방식과 기간은 조사·시안 검토 후 확정한다. 확인 전 일정이나 성능 수치를 약속하지 않는다.
