**RED** — 분류 호환 누락과 새 항목의 상태 판정 결함이 있습니다.

제 안은 전역 MUST를 유지하고, 과목별 목록을 렌더 함수에 인자로 넘기는 방식입니다. hw는 전용 판정기로 분리하고, 파일 type은 하나만 저장하되 읽을 때 구형 pre를 호환해야 합니다.

1. MUST 교체  
제시한 비동기 혼선은 확인되지 않았습니다. `v32-layer-src.js:282–285`는 콜백 안에서 해당 과목으로 dotsHTML을 호출합니다. 래퍼가 즉시 applyMust를 실행하면 동기 렌더 중 다른 콜백이 끼어들지 않습니다. 다만 전역 변경이 호출 뒤에도 남습니다. 인자 전달을 권고하며, 래핑을 유지한다면 기존 배열 내용을 보관하고 finally에서 복원해야 합니다.

2. hw와 상단 판정  
주차노트 링크 존재는 제출용 생성본 존재의 증거가 아닙니다. 안내 링크나 다른 회차 과제로도 충족될 수 있습니다. 과제 식별자·대상 주차/회차·산출물 종류를 연결하고, 링크만 있으면 ‘연결됨’으로 표시해야 합니다. V27.LOG의 실제 구조는 제공 근거에서 확인 못 했습니다. 상단은 조회 실패·동명 과목을 ‘없음’과 구별해야 합니다. CADD 영상도 과거 영상 하나로 매주 충족되지 않도록 주차를 구분해야 합니다.

3. classify 호환  
메모리 검사에서 구형 `{pre:1}`을 material로 읽으면 none입니다. 새 `{book:1}`을 기존 pre로 읽어도 none입니다. material만 pre로 별칭 처리하면 기존 교재·강의노트의 회차 판정이 사라집니다. 기존 pre 분류 전체를 호환하고 구형 JSON도 읽어야 합니다. 행을 복제하면 자료 개수가 중복되므로 읽기 집계에서 처리해야 합니다.

4. 추가 RED와 GREEN 조건  
초안의 hw를 kinds 없이 기존 kindState에 넘기면 TypeError가 재현됩니다. 교수필기 역시 기존 `KINDS_ATT`에 없어 올리기 버튼만 추가해선 입력 경로가 완성되지 않습니다. `_영상정리`는 현재 COMMON_DIRS에 없어 classify만 수정하면 탐색되지 않습니다(`_진도커버리지.py:212–214`).

GREEN 조건은 위 경로 수정과 구·신 JSON, 새 항목 업로드, 조회 실패, 과목 교차 렌더 검증입니다. 점 개수는 고정 2~3개가 아니라 실제 post 길이여야 합니다.
