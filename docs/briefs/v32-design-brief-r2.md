# V32 설계 회의 2차 — 오타 1차 RED 6건에 대한 수정안 (2026-09-16)

1차 안건: `v32-design-brief.md`. 1차 판정: `_v32-otta-1.md` (RED). 아래는 항목별 수용/반박. 반박은 2건(1-b, 3-a)뿐이고 나머지는 수용해 설계를 바꿨다. 파일 쓰기 없음. 코드는 아직 안 썼다.

## 1. 출결 집계 — 수용 + 부분 반박
- (수용) `attStats` 를 V32 에서 **덮어써** 6종을 집계한다: `n={present,late,vlate,ghost,excused,absent}`. `rate` 분자 = present+late+vlate+ghost+excused (출석 인정), 분모 held = status 있는 회차 − cancelled. `eff`(결석 환산) = absent + floor((late+vlate)/lta). 휴강(`s.cancelled`)은 held 에서 제외(기존엔 status 가 null 이라 이미 빠졌음. 확인: V3 패치가 cancelled 회차의 status 를 null 로 둔다 7176행).
- (수용) 머리행 `(결석/지각)` = `absent / (late+vlate)`. excused·ghost 는 머리행에 안 세고 색·약자로만.
- (수용) 학습 완료는 기존대로 `reviewed`(4467행). 출결 상태로 완료 처리하지 않는다. XP 추가 지급 없음.
- **(반박 1-b)** "excused·ghost 는 보충 대상이며 학습 후 복습 대상으로 전환"을 코드로 강제하는 것은 이번 범위 밖이다. 복습 큐(5866행)는 `status!=="absent"` 만 거르므로 excused·ghost 는 지금도 복습 큐에 들어간다. 이번엔 **주차표 셀에 「보충」 배지**를 붙이는 것까지만 하고, 보충 워크플로(무엇을 보고 채웠는지)는 미결로 남긴다. 근거: 요구는 "기록·파악"이지 보충 관리가 아니다.

## 2. 4종 판정 병합 — 수용
- 종류별 상태 3값: `have`(기기 첨부·슬롯 있음) · `pc`(PC 인벤토리에만 있음 → 「PC 보관 · 열기 미지원」) · `none` · `unknown`(idb 조회 실패 또는 library.json 못 읽음 → "확인 못 함", 미보유로 바꾸지 않음).
- 출처별 개수를 따로 표시(`기기 2 · PC 3`), 합산·병합 없음.
- **기존 "판서" 첨부 = 미분류.** 새 kind 문자열을 `필기본`·`칠판판서`로 신설하고, 기존 `판서`(필기본 올리기가 저장하던 값, 6155행)와 타임라인 사진(6288행 `kind:"판서"`)은 **「필기/판서 미분류」**로 필기본·칠판판서 두 줄 모두에 "미분류 N개 · 분류하기" 로 보인다. 분류하기 = 첨부 칸의 kind 셀렉트에서 바꿔 저장(`idb.put` 기존 경로). 판정에서는 미분류가 있으면 그 줄은 `unknown` 이 아니라 **`have?`(분류 필요)** 로 노란 점. 6288행 타임라인 사진은 앞으로 `칠판판서` 로 저장(그 사진 버튼 이름이 「칠판/판서」 성격이라 판단 — 아톰이 UI 문구 확인 후 결정, 다르면 `필기본`).
- `mustHTML` 을 V32 에서 **덮어쓴다**. 분모는 `MUST.length`, 완료는 `done===MUST.length`. 헤더 문구 "N / 4".

## 3. library.json — 수용 + 부분 반박
- 스키마: `{"schemaVersion":1,"generatedAt":ISO,"asOf":"2026-09-16","root":"study-materials","items":[{"id":"공업수학1/2026-09-11/판서_RL회로_전체.jpg"(상대경로),"course":"공업수학1","code":"COE3051"?,"date":"2026-09-11","type":"rec|pre|note|board|summary|hw|derived|other","tags":["hw"],"file":"…","size":n,"mtime":ISO,"source":"pc","accessible":false}],"common":[{"id":"공업수학1/_강의자료/…","course":"공업수학1","folder":"_강의자료","type":"pre","file":"…","size":n}]}`
- **(반박 3-a) courseId 는 넣을 수 없다.** 앱 과목 id 는 기기마다 `uid()` 로 생성된다(2280·4931행). 안정 키는 과목명이다. 앱이 `course` 이름으로 `term().courses` 를 찾아 붙인다. 이름이 안 맞으면 라이브러리 「미연결」 묶음에 둔다.
- 회차 연결 = `course+date`. 공통 폴더(`_강의자료`·`_교재`·`_정리노트`·`_과제`)는 **회차 판정에 안 들어가고** 라이브러리 「과목 공통」에만 보인다.
- 분류 규칙(파일명·폴더 문맥): `정리.md`→summary · `원본_녹음_*`·`녹음_*`→rec · `학습지_*.pdf`·`강의자료_*`→pre · `학습지_*.md|.txt`·`*_텍스트추출.txt`·`*_교정본.md`→derived · `필기_*`→note · `판서_*`→board · `과제_*_판서.*`→board+tags[hw] · `_과제/` 폴더→hw · 나머지 other. 제외: `_pdfprof`, `__pycache__`, 점으로 시작, `.py`.
- 스캐너는 `_진도커버리지.py` 의 12개 제한을 안 쓰고 **새 함수**로 전체 파일을 훑는다. 같은 스크립트 파일에 두되 별도 출력.
- **공개 배포 문제 = 아토 컨펌 없이 닫는다**: `knowledge/library.json` 을 `.gitignore` 에 넣어 GitHub Pages 에는 안 올린다(파일명에 교수 실명이 있음 — 지침 §4 위반 소지). atom `/study/` 로컬 서빙에서만 읽힌다. 공개 페이지는 「PC 인벤토리 없음」 상태로 동작.

## 4. 주차표 화면 — 수용
- 「달력」 탭 세그먼트 4번째 `주차표`(월·주·학기·주차표). `renderCal` 래핑, mode==="grid".
- 셀 줄 상시 표시 = `과목약칭 N일차 [출결약자]` (약자 A/L/VL/G/E, 출석은 약자 없음) + 자료 점 4개. 진도 문구·과제 태그는 **줄을 탭하면 펼침**. 색 + 약자 병행(색만으로 구분 안 함).
- 폰(≤600px) 기본 = **선택 주차의 요일별 목록**(세로), 「표로 보기」 토글 시 5열 표를 가로 스크롤(열 최소 140px). PC 는 표 기본.
- 머리행 `(결석/지각)` 은 표 위 과목 칩 줄에 표시.

## 5. N일차 — 수용
- `V32.meetings(c)` = `planned(c)` 에서 (a) `c.enrolledFrom`(신설, 기본 없음) 이전 날짜 제외 (b) `sessionOn` 이 `cancelled` 인 날짜 제외 → 순번. 정역학은 V32 패치에서 `enrolledFrom="2026-09-03"` 을 넣는다(V3 패치 근거, 9/3 수강정정). 결과: 정역학 9/7 = 1일차, 9/9 = 2일차, 9/14 = 3일차 — 아토 사진과 일치. 미적2 9/1=1 · 9/3=2 · 9/8=3 · 9/10=4 · 9/15=5 — 사진과 일치.
- 보강(추가 회차)은 `planned` 에 없으므로 세션 날짜가 planned 밖이면 그 날짜 뒤에 끼워 순번을 준다.
