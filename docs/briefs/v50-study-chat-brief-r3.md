# 학습 중 질문 패널(아톰·오타 동시 호출) 설계 브리프 r2 — 오타 1차 RED(5건) 반영 (2026-09-21)

r1의 화면·데이터 흐름은 유지. 아래는 오타 지적 5건에 대한 확정 설계.

## 1. 요청 상태 기계 (RED 1·4)
- 상태: `idle → sending → running(turn.role) → closed` + 예외 `unauth(401)` · `locked(잠금 거절)` · `http(비200·비SSE)` · `dropped(스트림 중간 종료)`.
- **입력 잠금 해제 = 스트림이 닫힐 때(reader done)만.** `done` 이벤트는 턴 종료라 말풍선만 확정한다. `error` 뒤의 빈 `done {}`는 무시. 턴 수 상한 없음(서버 흐름 최대 5턴 — 아톰·오타·아톰·오타·아톰). 전체 시간제한 없음, 경과 시간만 표시(`아톰이 답하는 중 · 1분 32초`).
- `dropped`: 「연결이 끊겼습니다. 서버는 계속 답할 수 있습니다」 + [기록 새로고침](GET 재조회). 완료 여부는 기록으로만 판단하며 자동 재전송 없음. `locked`: 초안 보존 + 「다른 창에서 답변 중」. `unauth`: 「atom 로그인 필요」(패널 열 때 `GET /api/conversations` 로 미리 확인, 401이면 입력 비활성).
- 패널·덱을 닫아도 진행 중 요청 객체(`V45.req`)는 앱 수명 동안 유지 — 다시 열면 같은 말풍선 이어서 표시. 다른 창의 전송·답은 `EventSource("/api/watch")`(atom 앱과 같은 브로드캐스트)에서 `conv_id===group` 인 `user/turn/token/done` 을 받아 반영하되, 내 스트림이 살아 있는 동안은 내 스트림만 쓴다(중복 방지: 요청 진행 중엔 watch의 token/done 무시, 종료 후에만 반영).
- 패널 헤더에 「아톰·오타 그룹 채팅과 같은 대화입니다」 한 줄.

## 2. 문맥 (RED 2)
- 덱 → 앱: `parent.postMessage({type:"mc-slide", v:1, deck, ...}, location.origin)` — `render()` 끝 + 앱의 `{type:"mc-ctx?"}` 요청에 응답. `#check` 에서는 안 보냄.
- 앱 수신 검증(전부 만족해야 채택): `e.origin===location.origin` · `e.source===$("#ntvFrame").contentWindow` · `data.type==="mc-slide"&&data.v===1` · `typeof data.deck==="string"` · **`data.deck===V45.expectDeck`**(openNote 때 src 파일명 `notes/<id>-slides.html` 에서 계산; 덱 아닌 노트면 null → 문맥 미지원) · 필드 자료형 검사.
- 앱 상한(수신 측에서 다시 자름): title 80 · partTitle 60 · label 80 · qn 80 · text 600(잘리면 `…(잘림)` 표기) · choices ≤6개 × 120 · my 200. 조립된 문맥 블록 전체 ≤1,500자(넘으면 text부터 줄임).
- 세대: `openNote` 마다 `V45.gen++`, `V45.ctx=null`, `expectDeck` 재계산. `closeNote` → `ctx=null`, expectDeck=null. 늦게 온 메시지는 deck 불일치로 버려진다. 패널이 닫혀 있어도 리스너는 boot 때부터 산다.
- 전송 시 `ctx` 를 **깊은 복사로 스냅샷**. `revealed===false` 면 정답·정오·보기 정답 표시를 넣지 않고 `내 답: (아직 안 풀었음)`; revealed 인데 `correct` 가 null(주관식 자기채점 전)이면 `판정 전`. 잘린 text 뒤에 「수식·그림은 생략됐을 수 있음 — 추측하지 말 것」.
- 기존 덱 5개에 v5b 패치를 같은 스크립트로 적용(멱등). 문맥 메시지가 안 오는 덱/노트는 칩에 `문맥 없음 · 덱 미지원`, 그래도 질문은 가능(과목·제목만).

## 4. UI 보강 (RED 4)
- 진입: 덱 뷰어 헤더 [질문] (덱·정리 노트 공통, `openNote` 화면 전부). studyunit(수업 내용 화면)에는 이번엔 없음 — .51.
- 화자 표시: `turn.role` 로 「아톰이 답하는 중 / 오타가 검토 중 / 아톰이 고치는 중 / 오타가 최종 판정 중」 그대로 상태 줄. `status` 이벤트는 상태 줄 보조 텍스트.
- 모바일: 시트 높이 `60dvh`, 하단 `padding-bottom: env(safe-area-inset-bottom)`, 키보드 올라오면 시트가 `visualViewport` 높이에 맞춤. Enter 전송은 `e.isComposing||e.keyCode===229` 면 무시.

## 5. 검증 (RED 5)
- 단위(jsdom, fetch 모킹): SSE 파서 — UTF-8 다바이트가 청크 경계에 걸림 · 한 청크에 이벤트 3개 · 이벤트가 두 청크에 걸침 · `error`→`done {}` · 5턴 흐름 · 중간 종료(reader error) → `dropped` · 오타 실패 문구가 `done.text` 로 옴.
- API 분기: 401 → unauth · 404/500/비SSE → http · 그룹 없음 → 비활성 · 잠금 거절.
- 문맥: origin 불일치 · source 불일치 · type/v 불일치 · deck 불일치(늦은 메시지) · 과대(각 필드 상한) · `#check` · revealed 전/후 · 자기채점 전.
- UI: 답변 중 닫기→재열기 상태 유지 · 덱 전환 시 ctx 초기화 · 한글 조합 Enter 무시 · `<img onerror>` 삽입 무해 · 답변 중 입력 비활성 · 기록 로드와 새 답 경합(기록 로드 뒤 진행 중 말풍선 유지).
- 헤드리스: 1180 오른쪽 열 · 390 시트 캡처, 넘침 0.
- 실연동: `GET /api/conversations` 200 + group 존재 확인. **실제 전송 1회는 아토 확인 후**(그룹 대화에 기록 남음).

## 6. r3 보강 — 오타 2차 RED(3건) (2026-09-21)
- **완료 판정 = 서버 기록 기준.** `/api/send` 스트림에는 전체 완료 이벤트가 없다(그룹 흐름이 끝나면 핸들러가 반환해 스트림이 닫힘 — server.py `_group_flow` 마지막 `done("assistant", final3)` 뒤 신호 없음). 따라서 스트림 EOF는 **「닫힘(미확정)」** 상태이고, 즉시 `GET /api/conversations/<group>` 로 기록을 다시 읽어 서버 메시지(id 있음)로 화면을 **교체**한다. 교체가 끝나야 `closed(확정)` 로 표시. 재조회 실패 시 「완료 확인 안 됨 · 새로고침」. 입력 잠금은 EOF에서 풀되, 서버가 아직 잠금 중이면 다음 전송이 `locked` 로 거절되고 초안이 보존된다(1절과 동일).
- **문맥 세대 왕복.** 앱은 `openNote` 마다 `gen=Date.now()+"-"+(++seq)` 를 발급하고, iframe `load` 때 `{type:"mc-ctx?",gen}` 을 보낸다. 덱은 받은 gen 을 `CTX_GEN` 에 저장하고 이후 모든 `mc-slide` 메시지에 `gen` 을 실어 보낸다. 앱은 `data.gen===V45.gen` 이 아니면 버린다(같은 덱을 다시 열어도 이전 창 메시지는 gen 불일치). gen 요청 전(덱이 먼저 render한 경우)의 메시지는 gen 없음 → 버려지고, 덱은 `mc-ctx?` 응답으로 현재 장을 다시 보낸다.
- **방송 경로 중복 제거.** watch(`/api/watch`)의 `token/turn/status` 는 **화면에 쓰지 않는다**. watch 는 `user`·`done`(conv_id===group) 을 받으면 **기록 재조회 예약**(디바운스 800ms)만 한다. 화면의 실시간 말풍선은 내 `/api/send` 스트림에서만 나오며 `provisional` 표시 → 재조회로 서버 메시지 id 와 교체. 재조회는 id 기준 병합(이미 그린 id 는 건너뜀)이라 늦게 온 방송·중복 재조회가 있어도 중복 말풍선이 생기지 않는다.
- 검증 추가: EOF 뒤 재조회로 교체(provisional 0개) · 재조회 실패 시 미확정 표시 · 같은 덱 재열기 후 옛 gen 메시지 거부 · gen 요청 전 메시지 거부 + `mc-ctx?` 응답 채택 · watch `done` 두 번 + 스트림 종료가 겹쳐도 말풍선 수 동일.
- **(3차 반영) 완료는 주장하지 않는다.** 서버 변경 없이는 요청의 종료를 확인할 방법이 없으므로 EOF + 재조회 성공 상태의 라벨은 「**기록 동기화됨 · 완료 미확정**」이다(`closed(확정)` 라벨 삭제). 그 뒤에도 watch 의 `turn/done`(group)이 오면 재조회해 새 턴을 이어 그린다 — 조기 EOF 뒤 서버가 계속 생성하는 경우가 이 경로로 화면에 반영된다. 「완료」 표시는 .51(서버가 요청 id 와 `flow_end` 이벤트를 내보낼 때) 에서만.
