# 강의안 작성 규격 v1.1 (2026-10-09, 오타 검수 반영)

과목별로 따로 도는 아톰 세션이 시험범위 내용을 학습앱 **강의실**에 넣을 때 이 규격을 따른다.
이 규격대로 만들면 앱이 그대로 재생한다: 스앵님이 강의 → 섹션마다 확인 문제 → 학습지 → 결과.
견본: `knowledge/lectures/statics-2026-09-14.json` (정역학 9/14, 오타 GREEN).

---

## 1. 수업 한 회차 커리큘럼 (모든 과목 공통)

| 순서 | 무엇 | 길이 | 강의안 칸 |
|---|---|---|---|
| 0 입장 | 지난 시간 회상 2~4문장 → 「오늘 목표는 N가지예요」 + 목표 3개 | 30초 | `recap`, `goals` |
| 1 섹션 강의 | 섹션마다 판서 단계를 따라 설명 | 섹션당 2~4분 | `sections[].script` |
| 2 섹션 확인 | 방금 예제의 숫자·조건만 바꾼 1문제 | 1분 | `sections[].check` |
| 3 반복 | 다음 섹션 (회차당 섹션 4~6개) | — | — |
| 4 학습지 | 5문제: 개념 확인 2 · 예제 변형 2 · 도전 1 | 10~15분 | `worksheet` |
| 5 마무리 | 결과 창 + 한 장 요약 | 30초 | `summary` |

**섹션 하나의 말 흐름** (대본은 이 순서로 쓴다)
1. 왜 배우나 — 이 절이 어디에 쓰이는지 한두 문장
2. 핵심 개념 — 쉬운 말로, 정의 먼저
3. 판서 단계별 설명 — 칠판에 써지는 것과 같은 순서로
4. 예제 하나 풀이 시연 — 숫자를 소리 내어 한 줄씩
5. 흔한 실수 — 실제로 자주 틀리는 것 하나
6. ★ 교수님 강조 — 수업에서 교수님이 실제로 말한 것만(녹음·필기 근거 있을 때)
7. 정리 한 줄 — 「정리: …」

## 2. 파일 두 개

### ① 강의안 `knowledge/lectures/<lessonId>.json`
`lessonId` 는 `knowledge/lessons.json` 에 이미 있는 회차 id (예: `statics-2026-09-21`, `em1-2026-09-16`, `calc2-2026-10-01`, `phys2-2026-09-30`).

```json
{
  "schemaVersion": 1,
  "lessonId": "statics-2026-09-21",
  "course": "정역학",
  "date": "2026-09-21",
  "sources": [{ "label": "근거 설명 (녹음·필기·교재 쪽)", "href": "notes/lessons/statics/2026-09-21.html" }],
  "goals": ["목표 1", "목표 2", "목표 3"],
  "recap": [{ "say": "지난 시간에는 …", "mood": "smile" }],
  "sections": [
    {
      "id": "s1",
      "title": "섹션 제목",
      "goal": "이 섹션이 끝나면 할 수 있는 것",
      "exam": "녹음: 교수님이 「…」라고 두 번 강조 (근거 없으면 이 줄을 빼기)",
      "check": "c1",
      "script": {
        "s1-1:0": [{ "say": "대사 한 문장", "mood": "neutral" }],
        "s1-1:1": [{ "say": "…", "mood": "serious" }]
      }
    }
  ],
  "worksheet": [
    { "id": "q3", "kind": "개념", "section": "s3" }, { "id": "q4", "kind": "개념", "section": "s4" },
    { "id": "w2", "kind": "변형", "section": "s2" }, { "id": "w3", "kind": "변형", "section": "s3" },
    { "id": "w1", "kind": "도전", "section": "s5" }
  ],
  "summary": ["암기 카드로 쓸 한 줄 요약", "…"]
}
```

- `script` 의 키 = 그 회차 **판서 단계 id**. 판서 단계 목록은 `python -I docs/tools/lecture_check.py <lessonId> --steps` 로 본다. **모든 판서 단계에 대사가 있어야 한다**(빠지면 강의가 그 판서에서 말없이 넘어간다).
- `mood`: `neutral` · `smile` · `serious` · `think` 중 하나.
- `check` 는 문항 **id 만**, `worksheet` 는 `{id, kind, section}` 으로 적는다. 문항 본문은 ②에.
- 섹션 `id` 는 `s1`·`s2` 꼴 문자열.
- 학습지는 정확히 5칸: `kind` 개념 2 · 변형 2 · 도전 1, `section` = 그 문항이 이어지는 섹션 id. 확인 문제와 같은 문항을 학습지에 다시 쓰지 않는다.
- 섹션 하나의 판서 단계는 판서 순서대로 **이어진 구간**이어야 한다(건너뛰거나 다른 섹션과 섞이면 오류).
- `exam` 은 교수님이 실제로 강조한 것만, **근거(녹음 시각·필기·판서·교재 쪽)를 문장 안에** 적는다. 근거가 없으면 칸을 뺀다.
- `sources` 의 label 에 무엇을 근거로 썼는지(녹음·필기·판서·슬라이드·교재 쪽) 적는다.

### ③ 검산 스크립트 `knowledge/lectures/<lessonId>.verify.py`
대본 예제, 확인 문제·학습지의 **정답과 오답마다 그 오답이 나오는 실수 계산**을 `assert` 로 다시 계산한다. 마지막에 `print('검산 문항: c1 c2 … w1 …')` 로 검산한 문항 id 를 전부 출력한다. `lecture_check.py` 가 실행해서 종료 0 · 확인·학습지 문항이 전부 그 줄에 있음 · 실행되는 assert(주석 아님)가 문항 수 이상인지 본다. 견본: `knowledge/lectures/statics-2026-09-14.verify.py`.

### ② 문항: 교실 데이터에 추가
확인 문제·학습지 문항은 그 회차 교실 파일(`notes/classroom/<과목>/<날짜>.html`)의 `quiz` 에 들어간다. 직접 고치지 말고 도구로 넣는다:

```
python -I docs/tools/lecture_add_quiz.py <lessonId> 문항.json
```
`문항.json` = 배열:
```json
[{ "id": "c1", "qn": "섹션 1 확인 · 짧은 이름", "html": "문제 (KaTeX: \\(...\\))",
   "choices": ["정답", "오답1", "오답2", "오답3"], "ok": 0,
   "ans": "풀이 + 오답마다 왜 틀렸는지", "nodes": ["mech.dot_apps"] }]
```
- id 규칙: 섹션 확인 `c1`~`cN`, 학습지 새 문항 `w1`~, 기존 `q1`~ 은 그대로 재사용 가능(자기완결이어야 함 — 「위 두 벡터」 같은 참조가 있으면 못 씀).
- 도구가 저장할 때 보기는 `[{"html": "…", "ok": true|false}]` 꼴로 바뀐다. 교실 파일을 손으로 고치지 않는다.
- 같은 id 를 다시 넣으면 그 자리에서 고친다(검수 수정용).

## 3. 글쓰기 규칙

- **근거 없는 말 금지.** 수업 정리·녹음·교수 필기·교재에 있는 것만. 「시험에 꼭 나와요」 같은 단정은 교수님이 실제로 말했을 때만, `exam` 칸에 근거와 함께.
- **말투**: 스앵님 해요체. 한 문장 40자 안팎(최대 80자). 「자,」「여기서 중요한 건」 같은 말버릇은 섹션당 1~2번.
- **대사에는 수식 기호를 쓰지 않는다**(대사창·음성으로 읽힌다). `U 점 V`, `루트 2`, `세타` 처럼 말로. 수식은 판서와 문항에만.
- **숫자는 전부 검산**: 예제·확인 문제·학습지 숫자는 파이썬으로 다시 계산해 본다. 오답 해설은 그 오답이 실제로 어떤 실수에서 나오는지 계산으로 맞아야 한다(9/14 오타 검수에서 걸린 부분).
- **문제는 자기완결**: 다른 문제·「위 벡터」 참조 금지, 필요한 값은 문제 안에.
- **확인 문제 = 그 섹션 예제의 변형.** 강의에서 안 다룬 것은 학습지 `도전`에만.
- 보기는 4개, 정답 1개. 오답은 흔한 실수에서 나온 값으로.

## 4. 검사 → 검수 → 반영

1. `python -I docs/tools/lecture_check.py <lessonId>` — 이 규격의 필수 조건(목표 3·섹션 4~6·학습지 5와 구성·보기 4와 정답 1·대사 80자·대사 속 수식 기호·판서 빠짐/구간·id 중복·근거 표기·검산 스크립트 통과)을 전부 **오류**로 검사. **오류 0** 이어야 다음 단계.
   도구가 못 보는 것(대본이 근거와 맞는지, 오답이 정말 그 실수에서 나오는지, 정답이 하나뿐인지, 확인 문제가 그 섹션 예제의 변형인지)은 2의 내용 검수가 본다.
2. 오타 내용 검수(대본이 근거와 어긋나는지, 정답·오답 해설 검산). GREEN 이면
3. 아톰(강의실 담당 세션)에게 「<lessonId> 강의안 됐어」 → 브라우저 검사 후 반영.
