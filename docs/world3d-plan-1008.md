# A++O 3D 세계: 대표실과 학교를 한 지도로 걸어 다닌다 (설계 v1, 2026-10-08)

대표님 10/8 결정
- 대표실과 학교로 이어지는 3D 공간. 내가 걸어서 이동한다(마인크래프트·로블록스처럼).
- **1인칭.** 내 팔과 손만 보이고 몸의 나머지는 만들지 않는다.
- **대표실 일러스트는 전부 3D로 교체.**
- **뼈대 먼저.** 꾸미기(가구 디자인·조명·힉스필드·NPC 걸어 다니기)는 시험(10/19~) 뒤.

## 1. 지도 한 장

```
 [대표실]──문──[연결 복도]──현관──[학교 복도]─┬ 교실 5 (정역학·미적2·공수1·물리2·CADD)
  대표 책상(맥·폰)                              ├ 자료실
  비서 책상 3(아톰·오타·토토 3D)                 └ 과제실
  창(서울 풍경 판)
```

- 좌표계 하나에 대표실·연결 복도·학교가 모두 있다. 지금 학교(space.js build)는 그대로 쓰고, 그 앞(+z)에 연결 복도와 대표실을 붙인다.
- 자료실·과제실은 지금 2D 화면(지도·표지판으로 감)으로 둔다. 3D로는 문과 방 껍데기만 만들고, 문 앞에서 E를 누르면 그 2D 화면이 열린다.

## 2. 모듈 (study-console/school/world/)

| 파일 | 하는 일 |
|---|---|
| `world-map.js` | 지도 전체를 장면에 짓는다. 반환값은 상호작용 대상(kind·id), 충돌 상자, 출발점(spawn: office·gate·corridor·교실별), 문 |
| `fp-controller.js` | 1인칭 조작. space.js에서 떼어 낸다: e.code 키(한글 상태 포함)·Shift 달리기·포인터 잠금·끌어서 보기·휠·터치 패드·충돌·걸음 흔들림·E 상호작용·조준 안내. **1인칭 팔·손**은 카메라에 붙인다(대기 흔들림·걸음 흔들림·누를 때 뻗기). 손 색은 대표님 아바타 설정값 |
| `space.js` (학교) | world-map + fp-controller를 쓴다. 앉기·칠판/책상 시점·학습 방식은 그대로. 대표실 문 → `/kingdom/?spawn=gate` |
| `office-world.js` (대표실) | 대표실 페이지(kingdom)가 불러온다. 일러스트 방 자리에 전체 화면 3D. 위쪽 한도 게이지·아래쪽 대화 바는 지금 HTML 그대로 위에 둔다. 맥 → `Company.open()`, 폰 → 지금 폰 열기, 비서 → 지금 선택·상태 보기, 학교 현관 → `/kingdom/study/school/?spawn=gate`. 비서 상태·말풍선은 office3d.js 규칙(잠·타자·시선·입)을 쓰고, 말풍선 DOM은 머리 위 화면 좌표에 띄운다 |

- 대표실과 학교는 다른 페이지다(서버·저장소가 다름). 같은 지도를 두 페이지가 똑같이 그리고, 현관을 지나면 그 페이지로 넘어가며 같은 자리(spawn)에서 이어 걷는다. 넘어갈 때 짧게 로딩이 보이는데, 로블록스의 장소 이동처럼 받아들인다.
- WebGL이 없거나 3D를 띄우지 못하면 지금 화면(대표실 일러스트·학교 2D)으로 돌아간다.

## 3. 뼈대 범위 (시험 전)

1. fp-controller 분리 + 1인칭 팔·손. 학교가 이걸로 돌아도 기존 검사(걷기·앉기·패드·키보드·학습 방식·동기화)가 모두 통과해야 한다.
2. world-map: 연결 복도·대표실 방(책상 4·맥·폰·창·문)·자료실/과제실 방 껍데기·현관.
3. office-world: 대표실 페이지 연결, 상호작용 4종, 비서 3D·말풍선, 게이지·대화 바 유지.
4. 대표실 업데이트 후보 등록 → 대표님 「지금 업데이트」.

**시험 뒤:** 가구·재질·조명 디자인(힉스필드), 창밖 풍경, 비서·스앵님 걸어 다니기, 소리.

## 4. 성능·기기

- 렌더러 하나, 픽셀 비율 최대 1.5, 단순 도형. 아바타는 1명당 삼각형 약 6천 개, 4명 합쳐도 3만 개 미만.
- 아이패드: 터치 패드(지금 것)와 끌어서 보기. 매직 키보드는 e.code로 읽는다. 폰(짧은 변 600 미만)은 지금처럼 인스타식 화면으로 가고, 3D는 띄우지 않는다.

## 4-1. 계약 (v2 — 오타 설계 회의 RED 반영, 10/8)

**A. 현관 이동(spawn)**
- 출발점마다 위치·바라보는 방향을 표로 정한다: `office`(대표 책상 앞, 창 쪽), `gate-office`(대표실 쪽 현관 안쪽 2m, 대표실을 향함), `gate-school`(학교 쪽 현관 안쪽 2m, 학교 복도를 향함), `corridor`, 교실별. 모르는 값이면 기본(`office`·`corridor`)으로 간다.
- 도착점은 전환 영역에서 2m 떨어진 곳이다. 도착 뒤 **1m 이상 걸어야** 전환 영역이 켜진다. 그래서 들어오자마자 되돌아가는 반복이 없다.
- 첫 렌더가 끝나고 눌린 키가 모두 떼어진 뒤에야 이동 입력을 받는다.
- 학교 부팅은 `?spawn=` 을 읽어 걷기 상태로 바로 들어간다(school.js 부팅에 추가).

**B. 입력·카메라 소유권**
- 상태는 `hidden / walking / transition / seated / overlay` 중 하나이고, 그 상태가 카메라와 입력을 소유한다.
- `fp-controller`가 소유하는 것: 키(e.code)·터치 패드·시선(포인터 잠금·끌기·휠)·이동·충돌 조회·상호작용 **요청**. 카메라에 쓰는 것은 `walking` 상태일 때만.
- 학교가 소유하는 것: 방·문, 착석, 카메라 전환(move), fixedView(dual·paper), 수업 선택·저장·동기화(`sessionQueue`·`sessionEpoch`·revision은 옮기지 않음).
- 지도는 구조물·출발점·충돌 상자·상호작용 대상만 만든다. 수업이나 대표실 API는 부르지 않는다.
- 상태를 벗어날 때 키·드래그·포인터 잠금·터치를 모두 푼다.
- **overlay 판정**: 대화 입력·업무 창·폰·패널·지도·학습 방식 창 중 하나라도 열려 있으면 overlay다. 포커스가 입력칸에 있어도 overlay다. overlay에서는 전역 이동 키를 무시한다(inert만으로는 막히지 않음).

**C. 대표실 연결(company.js 공개 함수 추가)**
- `Company.openPhone()`, `Company.selectStaff(id)`(지금처럼 참여자 토글 + 상태 창, company.js:36 동작 그대로), `Company.staffState()`(모드·시선·말풍선 글자), `Company.canLeave()`를 추가한다.
- `canLeave()`는 지금 검사에 `#msg` 초안과 `Office.busy()`(진행 중 응답)를 더한다.
- 그림 DOM(.gl-workstation 등)은 지우지 않고 CSS로 숨긴다. drawCast·날씨가 계속 같은 노드를 갱신하고, 3D는 그 상태를 읽는다.
- 말풍선은 머리 위로 화면 투영한다. 카메라 뒤·벽 뒤(머리까지 raycast)·화면 밖이면 숨긴다. 동료 시선은 실제 3D 위치로 계산한다.
- 3D가 켜져 있으면 office3d.js는 import하지 않는다(렌더러 하나).

**D. 나가기 방어**
- 공용 `leaveTo(url)` 하나를 대표실 현관·맥의 학교 아이콘·상단 학교 링크·모바일 링크가 같이 쓴다(company.js:70·123·135·171의 직접 이동 교체).
- `Company.canLeave()`가 거짓이면 이동하지 않고 「입력 중인 내용이 있어요」를 띄운다.
- 폰 iframe에는 `postMessage('atom:busy?')`로 묻는다. 300ms 안에 답이 없으면 「모름」으로 보고 이동 전에 한 번 확인한다.
- 학교 쪽은 지금 leave 절차(풀이 저장·성장 기록 정지·세션 저장·음성 정지·요청 무효화)를 그대로 쓴다. **저장이 실패하면 이동하지 않는다.**

**E. 부팅·배포**
- 대표실 3D 경로: 동적 import → 지도 생성 → 첫 렌더 완료를 기다린 뒤 `kingdom:ready`를 보낸다.
- 3D가 실패하면 지금처럼 그림 준비(artwork)를 기다리고 일러스트 화면으로 간다. 3D 경로일 때 artwork 검사는 3D 준비 확인으로 대체한다(그림이 없다고 실패하지 않게).
- **버전 묶기**: 원본은 study-console `school/world/`·`avatar3d.js`·`vendor/three*`다. 대표실 업데이트 후보를 만들 때(`kingdom_release.py prepare`) 이 파일들을 `kingdom/world/`로 복사하는 단계를 넣는다. 대표실은 상대 경로 `./world/...`로 불러온다. 그래서 대표실 승인 버전에는 지도·컨트롤러·아바타가 함께 고정된다. 학교는 자기 원본을 그대로 쓴다.
- 복사본에는 원본 커밋 해시를 적어 둔다(`kingdom/world/SOURCE`). prepare 때 두 쪽이 다르면 경고한다.

**F. 성능 (임시 통과 기준: 아이패드 30fps 유지)**
- 측정 항목: draw call·삼각형·프레임 시간. 세계 화면 구석에 숨긴 측정값(`window.__worldStats`)을 두고 검사가 읽는다.
- 스앵님은 플레이어가 있는 교실(또는 10m 안)에만 보인다. 대표실 비서 3명은 대표실 안에서만 갱신한다.
- 같은 책상·의자는 InstancedMesh로 묶는다.
- 충돌 상자는 지도를 만들 때 한 번만 계산한다. 경계도 지도 데이터에서 가져온다(z>1.7 같은 하드코딩 제거).
- 상호작용 raycast는 벽도 함께 검사해서 벽 너머 대상은 고르지 않는다.
- 회전·가상 키보드·백그라운드 복귀·WebGL 연결 끊김 때는 입력을 풀고, 연결이 끊기면 기존 화면으로 간다.

**v3 추가(오타 2차 회의 RED 조건 — 1단계 착수 허락, 아래는 2단계 이후 계약)**
- E-1 복사 기록 파일은 `kingdom/world/SOURCE.json`이다. 확장자 목록에 들어가야 스냅숏·fingerprint에 포함된다. 복사 디렉터리 구조는 원본과 같게 고정한다: `world/school/world/*.js`, `world/school/avatar3d.js`, `world/school/vendor/three*.js`. 모듈 안의 상대 import(`../avatar3d.js`, `../vendor/...`)가 원본과 똑같이 맞도록.
- E-2 SOURCE.json에는 원본 경로·커밋·**파일별 내용 해시(sha256)**를 기록한다. 복사 직전과 직후에 원본 해시를 다시 재서 다르면 prepare를 실패시킨다. 복사는 `state()` 스냅숏보다 먼저 끝낸다.
- B-1 대표실 overlay 목록: `#gl-os`·폰·`#msg` 포커스, `#pop`, `#office`(대화 로그), `#inbox`, `#mailbox`, `#syslog`, 업데이트 확인·적용 화면. 학교: `#panel[open]`, 보이는 `#chat`, `.setup-sheet`, `.map-sheet`. 입력칸(`input/textarea/select/contenteditable`) 포커스도 overlay다. 창이 겹쳐 열리면 **마지막 창이 닫혔을 때만** 이전 상태로 돌아간다(열린 창 개수로 판정).
- D-1 atom 폰 응답기가 집계할 것: `busy`, 첨부 `pending`, 대화별 `draftFiles`, `sendQueue`, `remote`, 일정 편집 iframe의 미저장 상태. 질의·응답에 요청 ID를 넣고, 양쪽에서 `origin`·`source`를 검증한다. 시간 초과면 **이동 금지**다(명시 확인 전까지). 나가기 요청이 연달아 오면 하나로 묶는다.
- 1단계 통과 조건: 겹친 창 차단(B)을 걷기만이 아니라 착석의 방향키·시선·터치·E 요청에도 적용한다. 걷기·착석·dual/solo/paper·저장 실패·다른 기기 동기화 검사를 통과해야 2단계로 간다.

**순서(오타 제안 그대로)**
1. 이 계약을 설계에 명시한다(이 절).
2. 지도는 그대로 두고 fp-controller만 분리한다. 걷기·착석·dual/solo/paper·두 기기 동기화 검사를 다시 통과한다.
3. 공용 지도와 현관 이동을 붙이고, 양방향 이동·저장 실패·재진입 반복을 검사한다.
4. 대표실 3D와 업무 DOM을 연결하고, 부팅 실패 복귀를 검사한다.
5. 아이패드 동선 검증 → 대표실 업데이트 후보. 손 뻗기 연출·장식은 뒤로.

## 5. 위험과 대응

- 대표실 상호작용(대화·결재·맥 창)은 company.js 기능을 그대로 부른다. 3D는 「어디를 누르면 무엇이 열리나」만 바꾼다.
- 일러스트보다 3D 도형이 투박하게 보인다(대표님이 감수하고 고른 것). 시험 뒤 디자인으로 메운다.
- 페이지 이동 때문에 대표실 대화 중 학교로 가면 대화 창이 닫힌다. 현관 앞에서 진행 중인 대화·입력이 있으면 「입력 중인 내용이 있어요」로 막는다(company.js canLeave).
