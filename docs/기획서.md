# 대학생 학습 코디네이터 웹앱 — 기획서

> **한 줄 정의** — 시간표만 올리면, 내 과목들이 책장에 꽂히고, 시험 날까지 무엇을 얼마나 어떻게 공부할지 매일 지시하는 **AI 학습 코디네이터**.
>
> *씽크빅(모르는 지점 진단) × 듀오링고(매일 하게 만드는 루프) × 김주영 스앵님(냉정한 전략 지시)*

- **작성일** 2026-08-27
- **작성자** 김아토 (한양대 기계공학과)
- **1차 목표** 학점 상승 (목표 GPA 3.5+)
- **1차 플랫폼** 웹 (아이패드 Safari 최적화) → 이후 네이티브 앱

---

## 1. 왜 만드는가

기존 학습앱의 공백:

| 기존 도구 | 하는 것 | 못 하는 것 |
|---|---|---|
| 에브리타임 시간표 | 시간표·강의평 | 학습 자체에 개입 안 함 |
| 노션·굿노트 | 자료 보관 | "지금 뭘 해야 하는지" 안 알려줌 |
| Anki | 암기 반복 | 계산과목·유도과정에 무력 |
| ChatGPT/Claude | 요약·질의응답 | 내 진도·출결·시험범위를 모름 → 매번 맥락 재설명 |

**빈칸**: *내 시간표 · 내 진도 · 내 출결 · 내 시험범위 · 내가 아는 것/모르는 것*을 전부 아는 상태에서 **매일 지시를 내리는 코디네이터**.

### 핵심 가설
1. 대학생이 학점을 못 올리는 이유는 "시간 부족"이 아니라 **어디부터 모르는지 몰라서** + **무엇부터 할지 몰라서**다.
2. 모르는 지점은 대부분 **해당 과목이 아니라 선수지식(고교 수학·물리, 공업수학)**에 있다.
3. 과목마다 **공부하는 방법 자체가 다른데**, 학생들은 전부 같은 방식(필기 정리 → 암기)으로 접근한다.

## 2. 서비스 컨셉 — "대학생판 김주영 스앵님"

AI가 맡는 4가지 역할:

| 역할 | 하는 일 | 산출 |
|---|---|---|
| **진단관** | 퀴즈·자가평가로 지식 구멍을 중·고등 기초까지 역추적 | "너는 동역학이 아니라 **벡터미적분**부터 무너졌다" |
| **설계자** | 과목 유형을 분석해 학습 루프를 설계 | "이 과목은 암기 0%, 유도 재현 70%다. 손으로 유도 3회." |
| **감독관** | 출결·출튀·복습·진도를 추적, 이탈 시 경고 | "3주째 열역학 복습 0회. 이대로면 C+." |
| **전략가** | 시험 D-day까지 남은 분량을 일 단위로 배분 | "D-9. 하루 4시간 × 9일 = 36h, 필요량 41h → 2개 챕터 버려라." |

**톤** — 단호하고 구체적. 위로 없음. 모든 지시에 숫자 근거를 붙인다.

## 3. 관리 범위 — 입학부터 졸업까지

이 앱의 시간 스케일은 3중 구조다. 바깥에서 안으로:

```
┌── 학적 (입학 → 졸업, 8학기) ───────────────────────────────┐
│  졸업요건 · 누적 GPA · 재수강 전략 · 지식맵                │
│  ┌── 학기 (16주 / 계절 4주) ──────────────────────────┐    │
│  │  책장 · 과목 · 출결 · 모드(평시/시험/회복)         │    │
│  │  ┌── 주차 (W1~W16) ───────────────────────┐        │    │
│  │  │  회차 로그 · 자료 4슬롯 · 복습 큐      │        │    │
│  │  └────────────────────────────────────────┘        │    │
│  └────────────────────────────────────────────────────┘    │
└────────────────────────────────────────────────────────────┘
```

학기는 리셋되지만 **학적 레이어는 졸업할 때까지 계속 누적된다.**

### 3.1 최초 온보딩 (앱 시작 전 1회)

```
1. 학교 · 전공        → 한양대 / 기계공학과 (복수전공·부전공 있으면 함께)
2. 학번 · 입학년도    → 2024학번, 2024-1 입학
3. 현재 학년 · 학기   → 2학년 2학기  ← 여기서부터 앱이 시작
4. 지금까지 들은 과목 → 학기별 · 과목명 · 학점 · 성적
                        (성적표 캡처 → 프롬프트 브리지로 일괄 파싱)
5. 졸업 요건          → 총 이수학점, 전공/교양 구분별 요구치
                        (학과 홈페이지 표 붙여넣기 → AI 파싱)
6. 목표               → 졸업 목표 GPA, 하루 가용 시간
   ↓
[졸업 대시보드] 생성  →  [이번 학기 책장] 생성
```

- 4번(기이수 과목)이 **가장 중요한 입력**이다. 이게 있어야 학점 역산도, 졸업요건 계산도, 재수강 전략도 나온다.
- 입력이 부담되므로 **성적표 캡처 → AI 파싱 → 표 확인/수정** 흐름으로 처리한다. 수기 입력은 보조 수단.

### 3.2 졸업 요건 트래킹

한국 공대 기준 요건 카테고리를 그대로 담는다.

| 구분 | 예시 요구치 | 표시 |
|---|---|---|
| 총 이수학점 | 130 | 진행 막대 |
| 전공필수 | 39 | 미이수 과목명 **직접 나열** |
| 전공선택 | 30 | 남은 학점 |
| MSC (수학·기초과학·전산) | 18 | 공대 필수 |
| 교양필수 | 12 | 미이수 과목명 |
| 핵심·일반교양 | 18 | 남은 학점 |
| 기타 요건 | 영어 성적 / 졸업작품 / 봉사 / 공학인증 | 체크리스트 |

**출력 형태**
```
졸업까지  84 / 130 학점  (64.6%)         남은 학기 4
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━░░░░░░░░░░░░░░

전공필수  21/39  ⚠ 미이수: 열전달, 기계진동, 자동제어, 캡스톤디자인(2)
전공선택  18/30
MSC       18/18  ✓
교양필수   9/12  ⚠ 미이수: 글쓰기와소통
기타       영어 TOEIC 700 미제출 ⚠

⚠ 4학년 1학기에 전공필수 4과목이 몰립니다. 3학년 2학기에 1과목 당겨 들으세요.
```

> 졸업요건은 "확인용 표"가 아니라 **수강신청 지시**로 이어져야 한다. 매 학기 수강신청 전에 "이번 학기에 반드시 들어야 하는 과목"을 앱이 먼저 말한다.

### 3.3 누적 GPA · 재수강 전략 (학점을 올리는 가장 빠른 레버)

목표 GPA 3.5에 도달하는 경로는 두 가지뿐이다. 앱은 **둘을 동시에 계산**한다.

**① 남은 학기로 끌어올리기**
```
필요 평점 = (목표GPA × (기이수학점 + 남은학점) − 기이수총점) / 남은학점

현재 2.98 (84학점) · 목표 3.50 · 남은 46학점
→ 남은 전 과목 평균 4.45 필요  ✕ 사실상 불가능
```

**② 재수강 병행**
```
재수강 1과목(3학점, C+ → A0) 효과 = +1.5 × 3 = +4.5 점
                                    → 누적 GPA +0.035

재수강 후보 (낮은 성적 × 학점 큰 순):
  1. 공업수학1  C0 (3학점)  → A0 시 +0.069  ★최우선
  2. 일반물리학 C+ (3학점)  → A0 시 +0.052
  3. 정역학     C+ (3학점)  → A0 시 +0.052   ※ 선수과목이라 재수강 시 후속과목도 같이 좋아짐

재수강 3과목 + 남은 학기 평균 3.9  →  목표 3.50 도달 ✓
```

- 앱은 **"이 조합이면 가능하다"** 를 구체적으로 제시한다. 불가능하면 불가능하다고 말한다.
- 재수강 후보 정렬 기준: `(4.5 − 현재성적) × 학점` 내림차순, 단 **선수과목 노드는 가중치 ↑** (후속 과목 성적까지 끌어올리므로)
- 학교별 재수강 제한(최고 학점 상한, 횟수 제한)은 온보딩에서 입력받아 반영

### 3.4 학기 계획 (8학기 로드맵)

```
       1-1   1-2   2-1   2-2   2-여름  3-1   3-2   4-1   4-2
학점    18    18    18    18*     3      18    18    15    12
GPA    2.7   2.9   3.1   3.4*   ---     3.8   3.9   4.0   4.0
누적   2.70  2.80  2.90  3.02   3.03   3.24  3.40  3.52  3.60 ✓
                          ↑현재                          ↑목표달성

* 현재 학기(진행 중) — 예측치
```
- 지나간 학기는 실적, 앞 학기는 목표치. **목표치를 조정하면 졸업 시점 GPA가 즉시 재계산된다.**
- 남은 학기에 어떤 과목이 배치되어야 졸업요건이 채워지는지도 이 표에 함께 얹는다.

### 4.1 메인 화면 = 책장 (Bookshelf)

**진입 플로우**

```
수강신청 확정
   ↓
에브리타임 시간표 캡처 업로드          ← 확정 방식 (§19.1)
   ↓
AI가 과목 파싱 → 과목명·교수·강의실·요일·교시  (학점은 확인 단계에서 보완)
   ↓
과목별 "책" 자동 생성 → 책장에 꽂힘
   ↓
책 클릭 → 과목 상세 진입
```

**정렬** — **학점 내림차순 (핵심 과목이 왼쪽 앞)**. 3학점 전공이 1학점 교양보다 항상 앞에 온다.
위험도는 정렬을 흔들지 않고 **책의 표시**(빨간 접힘 · 경고 태그 · D-n 라벨)로만 드러낸다. 매일 위치가 바뀌면 근육기억이 안 생기기 때문이다.

**책 한 권의 정보 밀도** (아이콘 하나에 담기는 것)

| 요소 | 시각 표현 |
|---|---|
| 과목명·학점 | 책등(spine) 텍스트 |
| 과목 유형 | 책등 색상 (계산형=청색, 암기형=녹색, 언어형=자색, 설계형=주황…) |
| 학습도(Coverage) | 책 두께 중 채워진 높이 |
| 이해도(Mastery) | 책등 하단 게이지 바 |
| 자료 결손 | 책등 모서리 **빨간 접힘 표시** + 결손 주차 수 |
| 출결 위험 | 책 상단 경고 태그 |
| 시험 임박 | 책이 앞으로 튀어나옴 + D-n 라벨 |

> 책장은 "예쁜 메뉴"가 아니라 **한눈에 보는 위험 지도**다. 얇고 빨간 책 = 지금 위험한 과목.

## 5. 학기 라이프사이클 — 앱은 학기마다 리셋된다

이 앱은 **영구 누적형이 아니라 학기 단위로 재구성되는 구조**다. 학기가 끝나면 그 학기는 통째로 아카이브되고, 새 학기의 빈 책장이 열린다. 넘어가는 것은 **지식맵과 학점 이력**뿐이다.

### 5.1 학기 사이클

```
1학기 (3~6월, 16주)
   ↓  [학기 종료 → 아카이브 → 책장 리셋]
여름 계절학기 (6~7월, 4주)  ※ 수강 시에만 생성
   ↓
2학기 (9~12월, 16주)
   ↓  [아카이브 → 리셋]
겨울 계절학기 (12~1월, 4주)  ※ 수강 시에만
   ↓
다음 학년 1학기 …
```

### 5.2 학기 전환 시 처리

| 데이터 | 학기 전환 시 |
|---|---|
| 과목 (책장) | **리셋** — 아카이브로 이동, 새 책장 생성 |
| 회차 로그 · 출결 | **아카이브** — 조회만 가능 |
| 자료 · 요약본 · 퀴즈 | **아카이브** — 검색 가능 (후배/재수강 대비) |
| **지식맵 (노드 상태)** | **이월** ★ — 학기가 바뀌어도 삼각함수는 여전히 삼각함수 |
| **학점 이력** | **누적** ★ — 목표 역산의 기준 |
| 게임 데이터 (XP·레벨·배지) | **누적** — 스트릭만 학기 경계에서 유지 |

> 핵심: **지식맵은 절대 리셋하지 않는다.** 1학년 때 진단한 "벡터미적분 취약"은 3학년 유체역학에서 그대로 유효하다. 학기마다 새로 진단하는 앱은 학생을 도울 수 없다.

### 5.3 계절학기 (압축 모드)

4주에 정규학기 16주 분량을 소화 → **밀도 4배**.

| 항목 | 정규학기 | 계절학기 |
|---|---|---|
| 주차 단위 | 주 | **일** (1일 = 정규 1주) |
| 복습 간격 | 1/3/7/16/35일 | **0.5/1/2/4/8일** (압축) |
| 시험 | 중간 + 기말 | 기말 1회 (또는 중간 1회) |
| 결석 허용 | 4회 내외 | **1회** — 경고 강도 최대 |
| 앱 모드 | 평시/시험 교대 | **상시 시험 모드** |

계절학기 생성 시 앱은 자동으로 압축 프로필을 적용하고, 상단에 `SUMMER · 압축` 태그를 띄운다.

## 6. 학기 내부 페이즈 · 주차 리듬 · 망각곡선

### 6.1 5가지 모드

앱은 **오늘 날짜와 시험 일정으로부터 현재 모드를 자동 판정**하고, 모드에 따라 화면 구성과 지시 내용을 바꾼다.

| 모드 | 시점 | 화면 | 코디의 지시 |
|---|---|---|---|
| `PREP` **준비기** | 수강신청 ~ 개강 전 | 시간표 업로드 · 강의계획서 수집 화면 | "강의계획서 6개 중 2개 없음. 오늘 채워라." |
| `NORMAL` **평시** | 개강 ~ D-15 | **책장** 메인 · 오늘 예습/복습 | "예습 1 · 복습 3. 47분." |
| `EXAM` **시험기간** | 시험 D-14 ~ 시험 당일 | **보스전** 메인 · 일별 배분표 | "신규 진도 중단. 열역학 문제풀이 4h." |
| `RECOVERY` **회복기** | 시험 직후 3일 | **오답 분석** 메인 | "중간 오답 18문항. 뿌리 결손 2개 발견. 오늘 처리." |
| `BREAK` **방학** | 학기 종료 후 | 아카이브 · 다음 학기 준비 | "다음 학기 동역학. 선수지식 벡터미적분 shaky. 방학에 12h." |

**모드 전환 규칙**
```
if (오늘 < 개강일)                        → PREP
else if (가장 가까운 시험까지 D ≤ 14)      → EXAM
else if (마지막 시험 종료 후 ≤ 3일)        → RECOVERY
else if (오늘 > 종강일)                    → BREAK
else                                       → NORMAL
```

### 6.2 정규학기 16주 구조

```
W1   W2   W3   W4   W5   W6   W7   W8   W9  W10  W11  W12  W13  W14  W15  W16
├────────┤├──────────────────────┤├────┤├────────┤├──────────────────┤├────────┤
  도입기         축적기            중간   회복기        심화기            기말
  PREP/NORMAL    NORMAL           EXAM   RECOVERY      NORMAL            EXAM
```

| 구간 | 주차 | 이 시기에 해야 하는 것 |
|---|---|---|
| **도입기** | W1–2 | 강의계획서 업로드 → 과목 유형 판정 → **기초 진단 퀴즈** → 선수지식 결손 발견 |
| **축적기** | W3–7 | 주차별 예습·수업·복습 3단 루프 정착. 복습 큐가 쌓이기 시작 |
| **중간고사** | W8 | 보스전 |
| **회복기** | W9–10 | 오답 → 뿌리 결손 추적 → 보강. **여기서 안 잡으면 기말에 똑같이 틀린다** |
| **심화기** | W11–14 | 후반부 진도 + 전반부 망각 복습 동시 진행 (부하 최대) |
| **기말고사** | W15–16 | 보스전 (범위가 전체인 경우 전반부 복습 상태가 승부를 가름) |

### 6.3 주차별 학습 단계 시각화

주차 타임라인을 **가로 16칸 게이지**로 상시 표시. 각 칸이 담는 정보:

```
 W1  W2  W3  W4  W5  W6  W7  W8  W9 W10 W11 W12 W13 W14 W15 W16
 ██  ██  ██  ▓▓  ██  ░░  ▒▒  ⚑   ··  ··  ··  ··  ··  ··  ⚑   ··
 ✓   ✓   ✓   △   ✓   ✕   ○  중간                        기말

 ██ 완료(자료+복습)   ▓▓ 부분   ░░ 결손   ▒▒ 진행중   ·· 미래   ⚑ 시험
```

- 칸을 누르면 그 주차의 회차 로그 · 자료 4슬롯 · 복습 상태로 바로 진입
- **결손 칸(░░)이 시험 ⚑ 앞에 몇 개 있는지**가 한눈에 보이는 것이 이 화면의 존재 이유

### 6.4 학습량은 주차가 갈수록 늘어난다

주차별 일일 학습량은 **신규 진도(거의 일정) + 복습 큐(누적 증가)** 로 결정된다.

```
일일 학습량(W) = 신규진도량 + Σ 복습예정(W)

W1  ▓                        0.8h   신규만
W3  ▓▓▓                      1.6h   1주차 복습 합류
W5  ▓▓▓▓▓                    2.3h
W7  ▓▓▓▓▓▓▓                  3.1h   ← 중간고사 직전, 이미 부하 높음
W11 ▓▓▓▓▓▓▓▓▓▓               4.4h
W14 ▓▓▓▓▓▓▓▓▓▓▓▓▓            5.6h   ← 최대 부하
```

**이 곡선을 학기 초에 미리 보여준다.**
> *"지금 하루 0.8시간이라 여유로워 보이지만, 14주차엔 하루 5.6시간이다. 지금 밀리면 그때 못 따라잡는다."*

밀린 복습은 큐에 계속 쌓이므로, 미이행분은 **빨간 오버플로 막대**로 곡선 위에 별도 표시한다.

### 6.5 망각곡선 기반 재확인 시스템

**모델** — 각 지식노드(또는 회차)마다 기억 강도를 추적한다.

```
잔존율 R(t) = e^(−t / S)
   t = 마지막 복습 후 경과일
   S = 안정성 (복습 성공할수록 증가)

복습 성공 → S ← S × EF   (EF 기본 2.2, 회상 품질에 따라 1.3~2.8)
복습 실패 → S ← 1        (리셋)

복습 예정일 = 마지막 복습일 + S  (R이 0.85로 떨어지는 시점)
```

**기본 복습 간격** (정규학기)
```
수업 당일 → +1일 → +3일 → +7일 → +16일 → +35일
```

**오늘의 복습 큐**
```
복습 예정일 ≤ 오늘 인 항목 전부
   ↓ 정렬
① 잔존율 낮은 순 (가장 잊어버린 것)
② 시험 출제 가중치 높은 순
③ 뿌리 결손과 연결된 것
```

**재확인 방식은 과목 유형에 따라 다르다** (§7 참조)
| 유형 | 복습 방식 |
|---|---|
| `CALC` | 그때 그 문제 **다시 풀기** (읽기 금지) — 5분 타이머 |
| `MEMO` | 플래시카드 회상 |
| `CONCEPT` | 30초 자기설명 |
| `LANG` | 문장 재노출 |

**과목별 기억 현황 그래프** — 시험범위 전체의 평균 잔존율을 시간축으로 표시하고, 시험일에 어디쯤 떨어져 있을지 **예측선**을 긋는다.
```
잔존율
100% ┤▔▔╲
     │    ╲___          ← 복습 없이 두면
 85% ┤ ╱╲    ╲___
     │╱   ╲╱▔╲    ╲___  ← 복습 개입 시
 50% ┤          ╲▔▔▔╲▔▔▔▔▔
     └──────────────────────→
     W3          W8(중간)   W15(기말)
```
> 시험일 예측 잔존율이 70% 미만인 노드는 **자동으로 시험 대비 큐에 강제 편입**된다.

## 7. 과목 유형 분석 엔진 (핵심 차별점)

### 7.1 분류 체계 — 2축

**축 A · 지식의 성격**

| 코드 | 유형 | 특징 | 대표 과목 |
|---|---|---|---|
| `CALC` | 계산·유도형 | 공식 유도 → 조건 대입 → 수치 산출 | 정역학, 동역학, 열역학, 유체역학, 공업수학 |
| `CONCEPT` | 개념·원리형 | 원리 이해 + 오개념 제거가 핵심 | 열전달, 물리학, 재료역학 개념부 |
| `MEMO` | 암기·분류형 | 분류·명칭·조건 암기량이 지배 | 재료공학, 생산공학, 기계요소 규격 |
| `LANG` | 언어·반복형 | 노출량 × 반복 주기 | 영어, 제2외국어 |
| `WRITE` | 산출·서술형 | 결과물 품질로 평가 | 글쓰기 교양, 보고서형 교양 |
| `MAKE` | 설계·프로젝트형 | 산출물 + 일정 관리 | CAD, 설계프로젝트, 캡스톤 |

**축 B · 평가 방식** (성적 배분이 어디서 나오는가)

`시험 문제풀이` / `객관식 암기` / `서술형` / `과제·보고서` / `발표·팀플` / `출석·태도`

→ 두 축의 조합으로 **학습 시간 배분 비율**이 결정된다.

### 7.2 유형별 학습 루프

#### `CALC` 계산·유도형 — 기계공학 전공 대부분
```
1. 개념 1회 통독 (요약본)          ─ 10%
2. 유도 백지 재현 (손으로)          ─ 25%  ★핵심
3. 예제 3문제 (풀이 보며)           ─ 15%
4. 유형별 문제 반복 (풀이 없이)     ─ 35%
5. 시간제한 세트 (시험 시뮬)        ─ 15%
```
- **측정 지표**: 유형별 정답률 + 문제당 소요시간
- **실패 신호**: "이해는 되는데 못 푼다" → 3번에서 4번으로 못 넘어간 상태
- **AI 지시 예시**: *"열역학 제2법칙, 이해도 자가평가 4/5인데 문제 정답률 42%. 개념 다시 보지 마라. 엔트로피 계산 유형 12문제부터."*

#### `MEMO` 암기·분류형
```
1. 분류표 만들기 (스스로)
2. 플래시카드 생성 (AI)
3. 간격 반복 (1일 → 3일 → 7일 → 16일)
4. 빈칸 채우기 → 백지 회상
```
- **측정 지표**: 카드별 회상 강도, 다음 복습 예정일
- **알고리즘**: SM-2 경량화 버전

#### `CONCEPT` 개념·원리형
```
1. 개념 지도 그리기
2. 파인만 기법 — 내가 설명 → AI가 채점
3. 오개념 함정 퀴즈
4. 반례 찾기
```
- **측정 지표**: 자기설명 통과율

#### `LANG` / `WRITE` / `MAKE`
- `LANG` — 일일 노출량 + 스트릭 중심 (듀오링고 루프 그대로)
- `WRITE` — 루브릭 자가채점 → AI 첨삭 → 재작성
- `MAKE` — 마일스톤 역산 + 산출물 체크리스트

### 7.3 유형 판정 방법
```
입력: 강의계획서 + 교수 수업방식 + 강의후기 + 평가 비중
  ↓
AI 분석 → { typeA, typeB, 시간배분비율, 주의사항, 교수 출제 성향 }
  ↓
과목 상세에 "학습 처방전" 카드로 고정 표시
```

---
### 7.4 평가 구성 입력 → **학습모드** 확정

유형(A/B)은 과목의 성격이고, **학습모드는 실제 주간 행동 배분 프리셋**이다. 같은 `CALC` 과목이라도 오픈북이면 공부법이 완전히 달라지므로, **평가 구성을 입력받아야 모드가 확정된다.**

#### 7.4.1 과목 등록 시 입력 항목

```
[이수구분]  전공필수 / 전공선택 / MSC / 교양필수 / 일반교양 / 기타(P·F)

[평가 구성]  ─ 합계 100%가 되도록
  □ 중간고사    ___%     □ 없음
  □ 기말고사    ___%     □ 없음
  □ 과제        ___%     회수 ___회
  □ 수시 퀴즈   ___%     주기: 매주 / 격주 / 비정기
  □ 발표·팀플   ___%
  □ 출석·참여   ___%
  □ 실습·산출물 ___%

[시험 형식]  객관식 / 주관식 계산 / 서술형 / 오픈북 / 실기   (복수 선택)
[기타]       족보 유통 여부 · 상대평가 여부 · 재수강 제한
```

> 이 입력은 **강의계획서 첫 주에 대부분 공개된다.** 강의계획서를 붙여넣으면 AI가 위 항목을 자동 추출하고, 사용자는 확인만 한다.

#### 7.4.2 학습모드 7종

| 모드 | 발동 조건 | 주간 행동 배분 | 실패 신호 |
|---|---|---|---|
| **M1 문제풀이형** | 시험 ≥ 50% + `CALC` | 유도 재현 25% · 문제 반복 50% · 개념 10% · 시뮬 15% | 이해는 되는데 못 품 |
| **M2 개념정리형** | 시험 ≥ 50% + `CONCEPT` | 요약 30% · 자기설명 30% · 오개념 퀴즈 25% · 문제 15% | 설명을 못 함 |
| **M3 암기반복형** | 시험 ≥ 50% + `MEMO` / 객관식 | 카드 간격반복 60% · 분류표 25% · 회상테스트 15% | 3일 뒤 다 잊음 |
| **M4 과제집중형** | 과제 ≥ 40% | 마감 역산 · 착수일 강제 · 루브릭 자가채점 | 마감 전날 착수 |
| **M5 산출물형** | 실습·설계 ≥ 40% | 마일스톤 분할 · 산출물 체크리스트 · 툴 숙련 | 진척 0인 주가 발생 |
| **M6 출석유지형** | 출석·참여 ≥ 50% & 시험 없음 | **최소 관리** — 출결만 추적, 학습 큐에서 제외 | 결석 누적 |
| **M7 수시평가형** | 매주/격주 퀴즈 존재 | **상시 소량 반복** — 매주 고정 슬롯 | 한 번 밀리면 복구 불가 |

- **M7은 병행 모드**다. 주 모드(M1~M5) 위에 겹쳐서 적용된다. → `M1 + M7` 형태
- **M6은 학습 큐에서 빠진다.** 교양 P/F 과목에 복습 큐를 배정하면 전공 공부 시간을 갉아먹는다. 앱은 **의도적으로 관리하지 않는 과목**을 만든다.

#### 7.4.3 판정 순서 (위에서부터 최초 일치)

```
1. 출석·참여 ≥ 50%  AND  시험 없음        → M6 출석유지형
2. 실습·산출물 ≥ 40%                       → M5 산출물형
3. 과제 ≥ 40%                              → M4 과제집중형
4. 시험(중간+기말) ≥ 50%
     typeA = CALC     → M1
     typeA = CONCEPT  → M2
     typeA = MEMO/객관식 → M3
5. 그 외                                    → 비중 최대 항목 기준으로 재판정

※ 수시 퀴즈 있음 → 위 결과에 M7 병행 추가
```

#### 7.4.4 시험 형식이 바꾸는 것

| 형식 | 학습법 변경 |
|---|---|
| **오픈북** | 암기 시간 → **0**. 대신 **정리노트/공식 인덱스 제작**에 시간 배분. 검색 속도가 점수 |
| **주관식 계산** | 부분점수 존재 → **풀이 과정 서술 훈련** 추가 |
| **객관식** | 함정·오답 선지 패턴 학습. 계산 속도 우선 |
| **서술형** | 답안 구조(정의→원리→적용) 템플릿 암기 |
| **실기** | 반복 숙달. 이론 학습 비중 축소 |

#### 7.4.5 모드는 학기 중에 바뀐다

```
중간고사 결과 입력
   ↓
예상 대비 실제 점수 낙차 분석
   ↓
낙차 원인 판정
   ├ 개념은 알았는데 계산 실수      → M1 유지, 시뮬 비중 15% → 30%
   ├ 문제 유형 자체를 처음 봄        → M1 유지, 문제 반복 50% → 65%
   ├ 개념을 몰랐음                   → M1 → M2 전환 (개념부터)
   └ 시간이 모자람                   → 시간제한 훈련 강제 편성
   ↓
기말까지의 모드 재설정 + 사용자에게 변경 사유 통보
```

> **모드를 자동으로 바꾸되, 왜 바꿨는지 반드시 말한다.** 이유 없이 바뀌면 사용자는 앱을 신뢰하지 않는다.


## 8. 자료 업로드 체계

### 8.1 과목 레벨 자료 (학기 초 1회)

| 자료 | 필수 | 쓰임 |
|---|---|---|
| **강의계획서** | ★필수 | 유형 판정, 평가 비중, 주차별 진도 |
| **교수 수업방식** | 권장 | 출제 성향, 필기 의존도 |
| **강의후기 / 강의평** | 권장 | 시험 난이도, 함정 포인트 |
| **기출 · 족보** | 권장 | 예상문제 정확도 급상승 |
| **시험범위** | ★확정 시 | 커버리지 계산의 기준선 |

### 8.2 회차 레벨 자료 (매 수업) — **4슬롯**

| 슬롯 | 시점 | 내용 | 산출물 |
|---|---|---|---|
| ① 강의자료 | 수업 **전** | PPT·PDF·교재 범위 | **예습본** (선수지식 체크리스트 + 잡아야 할 질문) |
| ② 필기 | 수업 **후** | 내 노트 사진·텍스트 | 요약본 정확도 ↑ |
| ③ 강의 녹취 | 수업 **후** | 녹음 → 텍스트 | *"교수님이 강조한 것"* 추출 ★ |
| ④ 공지·코멘트 | 수시 | 과제, 시험 언급 | 출제 힌트 |

**결손 표시** — 회차별로 4슬롯 중 몇 개가 비었는지 시각화.
> 책장에서 "3주차 ②③ 없음 · 7주차 전체 없음" 형태로 즉시 확인.

## 9. 학습도 · 이해도 정의 (숫자를 어떻게 만들 것인가)

세 지표를 **분리**해서 보여준다. 뭉뚱그리면 자기기만이 시작된다.

### 9.1 자료 충족도 (Data Coverage)
```
= 시험범위 회차의 채워진 슬롯 수 / (범위 회차 수 × 4)
```
→ *"공부할 재료가 갖춰졌는가"*

### 9.2 학습도 (Study Coverage)
```
= 시험범위 지식노드 중 '1회 이상 학습 완료' 노드 수 / 전체 범위 노드 수
학습 완료 = 요약본 확인 + 퀴즈 1세트 응시
```
→ *"한 번이라도 훑었는가"*

### 9.3 이해도 (Mastery)
```
노드별 이해도 = 최근 퀴즈 정답률(0.5) + 자가평가(0.2) + 유도 재현 성공(0.3)
             × 망각 감쇠 계수 (마지막 학습 후 경과일)

과목 이해도 = Σ(노드 이해도 × 시험 출제 가중치) / Σ(가중치)
```
→ *"시험장에서 실제로 나올 점수"*

### 9.4 화면 표시
```
전기전자공학  [자료 75%] [학습 60%] [이해 41%]   D-9
              ▓▓▓▓▓▓▓░░░ ▓▓▓▓▓▓░░░░ ▓▓▓▓░░░░░░
              ⚠ 결손: 5주차 녹취, 7주차 전체
```
**세 막대 사이의 낙차가 곧 진단이다.**
- 자료↑ 학습↓ → 게으름 (자료만 모으고 안 봄)
- 학습↑ 이해↓ → 방법 오류 (읽기만 하고 안 풂)
- 셋 다 ↓ → 위험 과목

## 10. 지식맵 · 진단 (씽크빅 축)

### 10.1 선수지식 그래프
중등 수학 → 고교 수학·물리 → 대학 수학 → 전공까지 **약 90개 노드**를 의존관계로 연결.

```
비·비율 → 문자와식 → 이차함수 → 삼각함수 → 벡터
                              ↘ 극한 → 미분 → 적분 → 미적분학 → 다변수 → 벡터미적분
                                                              ↘ 선형대수 → 상미분방정식
                                                                              ↓
                          자유물체도 → 평형방정식 → 응력·변형률 → 모어원 → 파손이론
                                                  ↘ 전단력선도 → 굽힘 → 처짐
```

각 노드: `{ 이름, 레벨(중등/고교/대학기초/전공), 예상학습시간, 선수노드[] }`

### 10.2 진단 로직

```
퀴즈 오답 발생
   ↓
오답 문항이 요구한 노드 식별
   ↓
해당 노드의 선수노드로 역추적 (재귀)
   ↓
"unknown/shaky 이면서 선수노드는 전부 known" 인 지점 = 뿌리 결손
   ↓
출력: "여기부터 시작하세요 — [삼각함수] (고교)"
```

### 10.3 학습량 계산
```
필요 시간 = Σ (노드 예상시간 × 상태 가중치)
  unknown = 1.0 / shaky = 0.5 / 미평가 = 0.35 / known = 0

예) 동역학 강체 운동역학까지 가려면
    미평가 3개 + shaky 2개 + unknown 1개 = 14.5h
    → 하루 3h 기준 5일
```

## 11. 게이미피케이션 (듀오링고 축)

### 11.1 루프 설계
| 장치 | 설계 | 이유 |
|---|---|---|
| **스트릭** | 연속 학습일 (하루 1회차 기록 or 퀴즈 1세트) | 매일 여는 이유 |
| **XP** | 회차기록 +10 / 복습완료 +20 / 퀴즈 만점 +30 / 뿌리결손 정복 +50 | 즉시 보상 |

| **보스전** | 시험 = 보스, 시험범위 노드 = 몹. 노드 정복률 = 보스 체력 감소 | 시험을 게임 목표로 전환 |
| **컨디션 게이지** | 하트 대신. 미복습·출튀 누적 시 감소 | 실패를 처벌이 아닌 상태로 |
| **배지** | 출튀 0회 4주 / 전과목 복습 100% / 기초노드 전복구 | 행동 교정 |

### 11.2 안 하는 것
- ❌ 하트 소진 후 잠금 (공부를 막으면 안 됨)
- ❌ 타인과의 리그 경쟁 (대학은 상대평가라 스트레스만 증가)
- ✅ 대신 **"과거의 나" 대비 궤도** 표시

## 12. 출결 · 학점 관리

### 12.1 출결 4상태 — **출튀를 별도 상태로 분리**

| 상태 | 행정 출석 | 실제 학습 | 처리 |
|---|---|---|---|
| 출석 | ○ | ○ | 정상 |
| 지각 | △ | ○ | N회 = 결석 1회 (설정) |
| **출튀** | ○ | ✕ | 행정상 안전, **학습 결손으로 기록** → 보강 대상 |
| 결석 | ✕ | ✕ | 학점 위험 + 학습 결손 |

> 출튀를 출석으로 처리하면 앱이 거짓말을 한다. 분리해야 이해도 계산이 정직해진다.

### 12.2 회차 로그 (수업 1회당 기록)
```
날짜 · 출결상태 · 진도(어디→어디) · 이해도 자가평가(0~5) · 복습여부 · 메모
```

### 12.3 학점 역산
```
필요 학기 평점 = (목표GPA × (기이수학점 + 이번학기학점) − 기이수총점) / 이번학기학점
```
→ 과목별로 *"이 과목 B+ 이상 필요"* 를 역산해 표시.

## 15. 데이터 모델 (요약)

데이터는 **학기(term)를 최상위 컨테이너**로 두고, 지식맵·학점이력·게임데이터만 학기 밖에 둔다.

```js
{
  // ── 학적 레이어 (입학 → 졸업, 절대 리셋 안 됨) ──────────
  profile:   { name, school, major, minor[], studentId, admitYear,
               targetGPA, dailyCap, 출결규정, retakeRule },
  degree:    { totalRequired,                       // 130
               buckets: [{ key:"전공필수", required, earned, missing:[과목명] },
                         { key:"전공선택", ... }, { key:"MSC", ... },
                         { key:"교양필수", ... }, { key:"일반교양", ... }],
               extras: [{ name:"TOEIC 700", done, note }] },
  history:   [{ termId, name, credits, gpa,
                courses:[{ name, credits, letter, bucket, retakeOf }] }],
  plan:      [{ termLabel:"3-1", plannedCredits, targetGPA, plannedCourses[] }],

  activeTermId,                          // 지금 열려 있는 학기
  terms: [{                              // ← 학기마다 하나. 종료 시 archived:true
    id, kind: "정규"|"계절",
    year, season: "1학기"|"여름"|"2학기"|"겨울",
    startDate, endDate, weeks,           // 정규 16 / 계절 4
    compressed,                          // 계절학기 = true → 간격·부하 4배 압축
    archived,
    courses:  [{ id, name, credits, prof, slots[],
                 typeA, typeB, 평가비중{},
                 강의계획서, 교수스타일, 강의후기, 기출,
                 examScope[], letter }],
    sessions: [{ id, courseId, date, week, status, 진도, 이해도, 복습여부, memo,
                 slots: { 자료, 필기, 녹취, 공지 } }],
    materials:[{ id, courseId, sessionId, kind, title, text }],
    outputs:  [{ id, courseId, kind: 예습본|요약본, content }],
    quizzes:  [{ id, courseId, items:[{ q, choices, answer, why, node, level }] }],
    attempts: [{ id, quizId, date, results[], score }],
    exams:    [{ id, courseId, kind:"중간"|"기말"|"퀴즈", datetime, scope[], weight }]
  }],

  // ── 학기를 넘어 이월되는 것 ──────────────────────────
  knowledge: { nodeId: { status, mastery, stability, lastAt, nextReview, ef, src } },
  reviews:   [{ id, targetType:"node"|"session", targetId, courseId,
                due, interval, ef, reps, lastResult }],   // 망각곡선 큐
  game:      { xp, level, streak, lastActiveDate, badges[] }
}
```

**파생 상태** (저장하지 않고 매번 계산)
```
phase        = PREP | NORMAL | EXAM | RECOVERY | BREAK   ← 오늘 날짜 + 시험일정
currentWeek  = (오늘 − startDate) / 7 + 1
todayQueue   = reviews.filter(r => r.due <= today)
weeklyLoad[] = 주차별 예상 일일 학습량 곡선
```

**저장** — 브라우저 localStorage(즉시·오프라인) + 클라우드 저장 버튼(기기 간 동기화) + JSON 백업 내보내기
**학기 종료** — `archived:true` 로 봉인 → 성적 확정치를 `history` 에 이관 → 새 term 생성

## 19. 확정 사항

| # | 항목 | 결정 | 설계에 미치는 영향 |
|---|---|---|---|
| 1 | 시간표 입력 | **에브리타임 캡처 이미지** 1순위 | 브라우저는 OCR 불가 → **이미지 파싱도 프롬프트 브리지**로 처리 (아래 19.1) |
| 2 | 강의 녹음 | **클로바노트 등 외부 앱 결과를 붙여넣기** | 앱 내 녹음/STT 구현 불필요. v1 부담 대폭 감소 |
| 3 | 교양·영어 | **v1에 포함** | `LANG` `WRITE` `MEMO` 학습 루프가 v1 필수 항목으로 승격 |
| 4 | 사용 범위 | **본인 + 타 전공 친구, 2인 기준 시작** (추후 확장 결정) | ★ **지식맵을 기계공학 전용으로 만들면 안 됨** → 전공팩 구조 (아래 19.2) |
| 5 | 책장 정렬 | **학점 높은 순 = 핵심 과목 우선** | 기본 정렬 고정. 위험도는 정렬이 아니라 **책의 표시**로 경고 |

### 19.1 에브리타임 캡처 → 책장 (확정 플로우)

```
에브리타임 시간표 캡처 (아이패드 스크린샷)
   ↓
앱에서 [시간표 등록] → 프롬프트 자동 생성 + 복사
   ↓
클로드 앱에 붙여넣기 + 이미지 첨부
   ↓
JSON 반환  [{ name, prof, room, credits, slots:[{day,start,end}] }, ...]
   ↓
앱에 붙여넣기 → 파싱 검증 → 책장 자동 생성
   ↓
사용자가 학점·교수명만 눈으로 확인 후 확정
```
- 캡처엔 **학점이 안 나오는 경우가 많음** → 파싱 후 학점 입력을 필수 확인 단계로 둔다 (정렬 기준이 학점이므로)
- v2에서 API 직결 시 이 단계가 이미지 첨부 1회로 자동화됨

### 19.2 전공팩 구조 (타 전공 대응)

지식맵을 **공통 코어 + 전공팩**으로 분리한다.

```
[공통 코어]  중등 수학 → 고교 수학·물리·화학 → 대학 수학
             ← 어느 전공이든 여기서 무너지는 사람이 대부분. 재사용.

[전공팩]  기계공학팩 : 정역학·고체·동역학·열역학·유체·열전달·기계설계·자동제어
          + 친구 전공팩 (추가 예정)
          + 교양팩 : 영어 / 글쓰기 / 통계 / 컴퓨팅

사용자 프로필에서 전공 선택 → 해당 팩만 로드
```
- **공통 코어(≈28노드)가 전체 가치의 절반**이다. 전공이 달라도 "삼각함수부터 무너졌다"는 진단은 동일하게 작동한다.
- 전공팩은 JSON 데이터일 뿐이므로, 친구 전공은 **강의계획서를 넣고 AI로 팩을 생성**해 추가하는 방식으로 확장한다.

### 19.3 2인 사용 · 공유 설계

| 항목 | v1 결정 |
|---|---|
| 데이터 | **각자 기기에 독립 저장** (계정 없음) |
| 공유 | 없음. 각자 자기 책장만 |
| 향후 검토 | 족보·요약본 공유, 스터디 스트릭 경쟁 — **3인 이상 확정 후 재논의** |

> 2인 단계에서 계정·서버를 만들면 개발 속도만 죽는다. 먼저 각자 쓰고, 실제로 공유하고 싶어지는 지점이 생기면 그때 붙인다.

## 20. 남은 결정 사항

1. **학기 시작일/종강일** — 자동 계산할 것인가, 매 학기 수기 입력할 것인가? (모드 판정의 기준이라 정확해야 함)
2. **시험 시간표** — 중간·기말 일정을 학기 초에 한 번에 넣을 것인가, 확정될 때마다 넣을 것인가?
3. **하루 가용 시간** — 고정값 1개인가, 요일별로 다르게 설정할 것인가? (알바·동아리 반영 여부)
4. **친구 전공** — 어떤 전공인가? 전공팩을 언제 만들 것인가?
5. **기출·족보 저작권** — 개인 보관은 문제없으나 공유 기능은 학교 규정 확인 필요

## 21. 부록 A — 실제 시간표 적용 예시 (2026-2학기)

### A.1 에브리타임 캡처 파싱 결과

| 과목 | 요일·시간 | 강의실 | 학점 | 이수구분(추정) |

### A.2 평가 구성 입력표 — **강의계획서 확인 후 채울 것**

아래 표가 채워져야 학습모드가 확정된다. 지금은 과목 성격만으로 **가설 모드**를 잡아 둔 상태다.

| 과목 | 중간 | 기말 | 과제 | 수시퀴즈 | 출석 | 발표·실습 | 시험형식 | 유형A | **가설 학습모드** |
|---|---|---|---|---|---|---|---|---|---|
| **정역학** | ?% | ?% | ? | ? | ? | — | 주관식 계산 | `CALC` | **M1 문제풀이형** |
| **공업수학1** | ?% | ?% | ? | ? | ? | IC-PBL ? | 주관식 계산 | `CALC` | **M1 + M7** (IC-PBL이면 수시평가 유력) |
| **미분적분학2** | ?% | ?% | ? | ? | ? | — | 주관식 계산 | `CALC` | **M1 문제풀이형** |
| **일반물리학2** | ?% | ?% | ? | ? | ? | — | 계산+개념 | `CONCEPT`+`CALC` | **M2 → M1** (개념 먼저, 이후 문제) |
| **아카데믹글쓰기** | — | ? | **높음** | ? | ? | — | 서술 | `WRITE` | **M4 과제집중형** |
| **CADD** | — | ? | ? | ? | ? | **실습 산출물** | 실기 | `MAKE` | **M5 산출물형** |
| **창업아이디어탐색** | — | — | ? | — | ? | **발표·팀플** | — | `MAKE`+`WRITE` | **M5 / M6** (평가비중 확인 필요) |
| **사회봉사** | — | — | — | — | 이수 | — | — | — | **M6 출석유지형** — 학습 큐 제외 |

**확인이 특히 중요한 3가지**
1. **공업수학1의 IC-PBL 강의실** — PBL 수업이면 매주 팀 과제·발표가 붙는다. 그러면 `M1`이 아니라 `M1 + M7 + M4` 삼중 모드가 되고, 주간 부하가 크게 바뀐다.
2. **오픈북 여부** — 정역학·공업수학1이 오픈북이면 암기 시간을 전부 **공식 인덱스 제작**으로 돌린다.
3. **창업아이디어탐색의 평가 비중** — 출석·참여가 지배적이면 `M6`으로 내려 **학습 큐에서 제외**한다. 이 과목에 시간을 쓰면 정역학 시간이 줄어든다.

> 이 표의 빈칸을 채우는 것이 개강 첫 주의 **유일한 과제**다.

### A.3 이 시간표가 검증해 준 것

**① 유형 체계가 실제로 맞는다** — 6개 유형 중 5개(`CALC` `CONCEPT` `WRITE` `MAKE`, 그리고 P/F 예외)가 한 학기에 전부 등장. 학습법을 과목마다 다르게 줘야 한다는 전제가 실물로 확인됨.

**② 학점 순 정렬 시 책장 순서**
```
[정역학 3]  [공업수학1 3]  [미분적분학2 3]  [일반물리학2 3]
  ↑ 전공 첫 관문. 여기가 무너지면 3~4학년 전공 전체가 무너짐

[아카데믹글쓰기 3?]  [CADD 2?]  [창업아이디어탐색 2]  [사회봉사 1]
```
동점(3학점)일 때 2차 정렬은 **전공 > MSC > 교양** 순으로 둔다. 그래야 정역학이 맨 앞에 온다.

**③ 시간 부하 구조**
```
월  11:00-13:00 창업 / 15:00-16:30 정역학          — 여유
화  09:00-10:30 미적2 / 11:00-13:00 글쓰기 / 13:00-19:00 CADD  ← 최대 부하일
수  09:00-10:30 공수1 / 10:30-12:00 물리2 / 15:00-16:30 정역학  ← 3연강
목  09:00-10:30 미적2                              — 최대 여유
금  09:00-10:30 공수1 / 10:30-12:00 물리2          — 오전만
```
- **화요일은 학습 계획에서 제외**해야 한다 (CADD 6시간 실습 후 복습 불가)
- **목요일 오전 이후 전체가 비어 있음** → 주간 복습 큐의 주 소화 지점
- 복습 큐 배분은 요일별 가용시간을 반영해야 함 → §20 남은 결정사항 3번(요일별 가용시간)이 **필수**임이 확인됨

**④ 지식맵에 전자기·파동 노드 추가 필요**
현재 지식맵은 역학 계열 중심이라 **일반물리학2(전자기·파동·현대물리)** 를 담지 못한다. 다음 노드를 공통 코어에 추가한다.
```
전하·쿨롱법칙 → 전기장 → 전위 → 축전기
                  ↓
              전류·저항 → 회로(키르히호프)
                  ↓
        자기장 → 앙페르법칙 → 전자기유도(패러데이) → 인덕턴스 → 교류회로
파동 → 중첩·간섭 → 정상파 → 빛의 간섭·회절
```

### A.4 이 학기의 진단 (앱이 내놓을 첫 지시)

```
2026-2학기 · 18학점 · 계산과목 4개 (12학점)

⚠ 이 학기의 성패는 [공업수학1]에 달려 있다.
   공업수학1 = 상미분방정식 + 라플라스 + 선형대수
   → 3학년 동역학·자동제어·열전달의 공통 선수과목
   → 여기서 C 받으면 3학년 전공 3과목이 연쇄로 무너진다

⚠ 정역학은 전공의 첫 관문이다.
   정역학 → 고체역학 → 기계요소설계 로 3년간 이어진다.
   선수지식: 벡터(고교), 뉴턴 3법칙(고교) — 진단 퀴즈 먼저 볼 것

✓ 미분적분학2 · 일반물리학2 는 공업수학1·정역학의 선수지식과 겹친다.
   → 따로 공부하지 말고 묶어서 학습할 것 (시간 30% 절약)

첫 과제: 강의계획서 8개 업로드 → 유형 판정 → 기초 진단 퀴즈
```

> 이것이 이 앱이 존재하는 이유다. 시간표만 보고도 **"이번 학기는 공업수학1이 전부다"** 라고 말해 주는 것.
